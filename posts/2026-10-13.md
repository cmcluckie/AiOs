AiOS, part 3.  "I added a second program.  The operating system changed by zero lines."...

Towers of Hanoi.  If you did first-year computer science you did this one, probably the same week you met recursion.  Three pegs, a stack of disks, move them all over one at a time, never a big one on a small one.  Four disks, fifteen moves.

I'll admit it: recursion was one of my favourite things in college, and it's still one of the concepts in computer science I love most.  A function that solves a problem by calling itself on a smaller version of the same problem, trusting it'll work, and it does.  The whole Hanoi solution is about six lines.  I still think that's a little bit magic, and I loved getting to put it in here.

It also needs nothing new from the machine.  It writes and it stops, exactly like hello world.

So it's not really a test of Hanoi.  It's a test of the idea.  On Friday night I made a big deal about how this thing has to be built out of bricks, not a cardboard box you throw away every time you want something new.  Hello world was built as a tenant from day one, talking to the machine only through a little two-entry door, write and exit, so that the next program wouldn't have to tear anything down.

Well.  Here's the next program.  We built hello world.  Then we built Hanoi.  The loader, which is the closest thing this has to an operating system, came out byte-for-byte identical both times.  Same hash.  The diff to the operating system is zero lines.

Isn't that cool?  On a normal computer that sentence doesn't even make sense, because the operating system is the thing you install everything into.  Here it's a hundred and seventy lines that don't notice you added a program.

From here every program on the ladder gets to ask for exactly one new thing.  Memory next.  The first one where the diff isn't zero, and the first one where I find out whether the bricks were really bricks.

Still running in emulation on a borrowed machine.  The real build box isn't set up yet.  I'm a dad.  It'll happen.
