AiOS, part 4.  "If those 57 lines of Linux change, how the hell would I even know?"...

Sunday morning, coffee, a kid somewhere in the house, and a thought that ruined my coffee.

In part 1 I took 57 lines out of Linux's serial driver.  Linux changes every single day.  So when those 57 lines change upstream, what happens to me?

This is the problem every Linux distribution lives with.  They carry the whole tree and merge it forever, and inherit every conflict along the way.  It's a treadmill with no off switch.  And I'd just signed up for the same treadmill, only smaller, and if I'm honest I had no idea how I'd pull those 57 lines back in.

And there's a bigger question under that one, the one I'd ask about any product.  What was asked for?  What got built, why, what problem was it solving, and how was it built?  And how do we know that little sliver does exactly what it's supposed to?  I'm not asking for a formal proof.  I'm asking for the basics: a spec somebody wrote down, and unit and integration tests written off it.  For those 57 lines, as far as I can find, there isn't one.  The file says HP wrote it in 2004, based on code from 2001, and Linux's own git history only starts in 2005 with a first commit that literally says "I'm not bothering with the full history."  As a product guy that drives me a little nuts.  As someone who loves history, it's kind of sad.  So every piece we take gets what it never had: a spec, a test, and a record of exactly where it came from.

Turns out git has had the answer since 2013 and almost nobody uses it.  You can ask git "did anyone touch lines 86 to 98 of this file since this commit?" and it names the commits.  Line by line, following them around the file as other code moves.

So now every piece we take from Linux comes with a little record: which repo, which commit, which day, which file, which lines, and a fingerprint of the file at that moment.  Not a comment.  Something a script can check.  And the watch is one script that asks git that question for every range we've ever taken.  Silence means nothing moved.  A line means a human goes and reads the change and decides.  Nothing ever merges by itself.

I tested it by pretending we'd taken the lines back in April 2025.  It named the one commit that touched them since.  Put the real date back, it went quiet.  If you know a better way to do this, I'd love to hear it.

Two other things from the same morning.  What we wrote and what we took from Linux now live in separate folders under separate licences, because mixing them is how repos turn into a swamp.  And there's a play button now.  Open the repo in your browser, hit F5, pick something, watch it boot.  You don't have to install a thing.

Want to follow along at your own pace?  The blog post walks through the files to read, in order, and one small thing to try yourself.
