# Definition of done

*The story behind AiOS, part 7.*

## The confession

I'm a product manager.  The products I look after have been around for a
long time, and the thing I've learned matters most with an old product isn't
features.  It's being able to answer four questions about any piece of it.
What was asked for?  What actually got built?  Why was it built that way?  And
how do we know it does what it's supposed to?

When a team can answer those, a product is safe to change.  When nobody can,
it gets scary.  People stop touching the old bits, the old bits rot, and
eventually somebody proposes rewriting the whole thing from scratch, which is
almost always a mistake.

I spent part 4 of this series complaining that Linux can't answer those
questions about its own serial driver.  Then, six posts in, I asked them about
my own project.  And I couldn't answer them either.

## What was missing

Not everything.  But enough to be embarrassing.

- **As-built descriptions.**  Each part is supposed to have a plain document
  saying what it really does: every port it touches, every byte it writes, how
  big it is.  Most did.  The machine definition, the virtual hardware
  everything runs on, didn't.  Its index entry pointed at a file that didn't
  exist.
- **Specs.**  The loader that came with the calculator had no spec of its
  own.  Its tests were technically pointing at the previous two versions.
- **Tests that had actually run.**  This is the big one.  We had sixteen
  tests, each written down with exactly what makes it fail.  Hardly any had
  been run by anything except me, by hand, comparing output.  A few had never
  been run at all.  The project's own rules say a test only counts once it's
  been seen to fail.  By that standard, almost nothing counted.

How did it happen?  The same way it always happens.  We were moving fast, each
night something new booted, and the paperwork felt like it could wait until
tomorrow.  I've watched that exact pattern on real teams for years, and I'd
have told any of them to stop.

## What we did about it

First, the catch-up.  The machine got its as-built description, written from
the actual list of devices the emulator presents.  The calculator's loader got
a spec and a test.  The part we took from Linux got a test that checks its
record of where it came from against Linux itself.

Then the honest bit.  Every blog post now ends with two sections.  **As
built** links the description of every part in that post.  **Addendum: the
tests** lists every test for those parts: what it checks, what turns it red,
and its real status.  "Checked by hand, passed."  "Partly checked."  "Not run
yet."  A lot of them say "not run yet."  I'd rather show that than hide it.

## Making it stick

Fixing it once is easy.  Keeping it fixed is the hard part, and I don't trust
myself to remember at 11pm with a beer.

So the project's rules now have a section literally called **Definition of
done**.  Nine things have to be true before any part counts as finished or gets
a post: it has an index entry, an as-built description, at least one spec,
a test for every spec, a recorded result for every test, an origin record if
any of it came from Linux, every older program still running on it, a post
that passes the post checker, and every commit in the ledger.

And two small scripts that check it, because a rule nobody checks is a
suggestion.  One reads every post and blog post and names anything out of
format.  The other reads every part in the index and names anything that
breaks the definition of done, by part and by rule number.

I ran the new checker against this morning's version of the repo.  It failed
on exactly two things: the loader with no spec, and the machine with no as-built
description.  The same two gaps I'd found by hand.  Against today's version,
it passes, and it still says, honestly, that sixteen tests have never been run
by an automatic runner.  That's the next job.

## What I learned

Nothing here is clever.  Every team knows it should write down what it built
and test it.  Every team skips it when it's having fun.  The only thing I've
ever seen actually work is the boring combination of writing it down as a rule
and having something dumb that won't let it slide.  A checker doesn't get
tired, doesn't get excited about the shiny new feature, and can't be talked
out of it.

It's the same idea the whole project rests on.  The clever thing proposes.
The dumb thing decides.

## Try this

Open the repo in Codespaces, open a terminal, and run `sh jig/donecheck`.  It passes.  Now rename any file in index/cmp that ends in `.as-built.md` and run it again: it names the part and says "rule 2: no as-built spec."  Rename it back.  That's a dumb, honest gatekeeper doing its job.

## Addendum: the tests

The tests written in this catch-up.  "Checked by hand" means run and compared, but not yet by the automatic runner (plan section 4), which is the next post.

**serial.8250@1**

- [serial.origin-matches@1](https://github.com/cmcluckie/aios/blob/main/tests/serial.origin-matches@1.toml).  Checks: every line range in the part's record of where it came from matches Linux at the recorded commit.  Goes red when: `jig/upstream verify` reports any range as WRONG.  Status: Run, 2026-10-11: all 16 ranges match.  Not yet seen going red.

**loader@3**

- [loader.read@1](https://github.com/cmcluckie/aios/blob/main/tests/loader.read@1.toml).  Checks: the read door waits for at least one byte, returns what's arrived in order, and never more than asked; the older doors don't move.  Goes red when: the calculator's transcript isn't exact under this loader, or hello, Hanoi or Life differ by one byte under it.  Status: Checked by hand, 2026-10-11: passed.

**The checkers themselves**

- `jig/donecheck`, run against this morning's repo: red, naming loader@3 (rule 3) and machine.serial-only@1 (rule 2).  Against today's: green.
- `jig/postcheck`, broken on purpose three ways in part 3 and once in part 5: red each time, naming the file and the rule.  Restored: green.
