# Findings 0030: the race, set

Source: part 22, after findings 0029 and TST.share.waits@2 (decision 0105),
2026-10-29.  Chris: "So lets go?"  Goes to: the architects (Chris and Claude).

1. **What the race is.**  Findings 0027 item 2g: the exam's three items (serial,
   timer, screen) on both benches, the same model on the card, the same pinned
   source, graded on ceiling: which bench, peak context, and whether a run ended by
   passing, out of room or stuck.  Dollars logged, not graded.

2. **What was missing.**  The layered agent could only fix: a builder gets a red
   test and a copy of the repo, and changes existing files under pool/.  An exam
   item is a lift: a new C file written from a question, reading Linux.  jig/sit
   does that; the agent could not.

3. **The lifter (decision 0106, SPEC.agent.12).**  A job that names `exam = ITEM`
   in place of a test is a lift.  It is shown exactly what jig/sit shows: the
   question, the name of the C file and the fixed header.  It never sees the repo,
   so never the hand lift.  Its tools are read_linux (jig/reader on the jig, each
   read with a why), write_file (only the file the item asks for) and submit_lift.
   A lift passes when every one of the item's tests prints PASS with it in the
   hand lift's place.  That is jig/judge's rule, run the way the builder's judge
   runs a fix, so the note has every test's line and not only the first red one.
   Before any call the hand lift must pass the same tests, as jig/sit checks.  The
   run is recorded under the item's name, so the card sets the two benches side by
   side.  A part plan names `exam = ITEM` in place of tests.  The lifter's system
   prompt, prompts/lifter@1.txt, is exam/prompt.txt with the tools in place of
   "the finished file and nothing else", and builder@2's "think briefly, then act".

4. **The plans.**  agent/plans/race-serial.toml, race-timer.toml and
   race-screen.toml: the item, from d1abf44, director@2 and lifter@1, gear 1, 10
   tries, 240 minutes.

5. **Ruled for the race, 2026-10-29.**  Each bench keeps its own caps: jig/sit is
   frozen (decision 0104), so its 3 tries of 25 calls and 8,000 tokens a reply are
   part of the control; the layered agent has its plan's.  The card shows both.
   Each item three times on each bench, 18 runs, because one pair proved nothing
   on waits (findings 0029 item 7).

6. **The same card on both.**  jig/sit calls the card through jig/model, whose
   context is MODEL_NUM_CTX (default 32,768); the layered agent's is 98,304.  The
   race sets MODEL_NUM_CTX=98304 for jig/sit, so the two differ only in the bench.
   That is how jig/sit is run, not a change to it.  jig/sit runs on the jig, which
   reaches Ollama on Windows through a port forward on the host's address on the
   jig's network (findings 0026 item 5, 172.19.224.1).  The jig's network has
   moved since (the jig is at 172.27.225.162), so the forward is checked before
   the first jig/sit run.

7. **Read by Claude: what is not the same.**  The layered director's prompt,
   director@2, speaks of red tests and a clean checkout; on an exam plan its "test"
   is the item.  It was not rewritten for lifts: a director that reads its notes
   and gives a hint is the thing being raced.  jig/sit cuts a reader's answer at
   20,000 characters; the lifter's at 8,000, the builder's look limit.  Both are
   each bench as built.
