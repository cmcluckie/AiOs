# Findings 0016: the decision ledger, small, and what it cannot see yet

Source: part 15, 2026-10-14.  Chris's point: a test proves the code does what
was asked, not that the agent did it the way it was meant.  Built to his specs
SPEC.ledger.1@1 and SPEC.referee.12@1.
Goes to: humans who own the constitution.

1. **What was built.**  constitution/human-only.toml lists, by path, what only
   a human decides: tests, specs, purposes, capabilities, dependencies, the
   licence, and the rules and words.  A decision is a TOML file in decisions/.
   `jig/aios ledger` refuses a change to any of those paths unless a decision
   in the same change names it, decided by a key in constitution/keys/.  It
   runs before every commit from .githooks/pre-commit.  Code is not on the list:
   writing it is the agents' job.

2. **Rule 12.**  A program touches no hardware: the referee reads each
   program's own assembly after the build and refuses port I/O or a privileged
   instruction.  The demonstration is hello rewritten to drive the serial port
   itself: its output is byte for byte hello's, so hello's test passes it, and
   the referee refuses it.

3. **The ledger checked itself first.**  This change touched the rules, the
   schema, two specs and two tests, all human-only, so it could not pass its
   own check until decisions/0001.toml and 0002.toml were drafted for Chris.

4. **What it cannot see yet**, so nobody reads more into it:
   - `by` is a claim.  An agent can type any key's name.  Until commits are
     verified against constitution/keys (plan 3.5), the proof a human decided
     is Chris's signature on the commit that carries the decision.
   - The hook can be skipped: `git commit --no-verify`.  The same check has to
     run again where it cannot be skipped: on the jig, and later at admission.
   - Rule 12 reads assembly, not the binary.  Machine code typed in as raw
     bytes would get through.  The real fix is not a cleverer check but ring 3
     (plan 9.13): a program the processor itself forbids from port I/O.
   - It knows paths, not meaning.  It catches the agent that changes a test; it
     does not catch the agent that writes its own version of something the
     catalogue already has.  Rule 12 catches one kind of that, the hardware
     kind.  The general kind needs the quartermaster's decisions to be
     checkable against the code, which is its own post.
