# Findings 0012: the jig's first run

Source: the jig, NixOS 26.05 in a Gen 2 Hyper-V VM on the Windows box, KVM
inside it (nested virtualization), 2026-10-12.  First run of every test under
KVM instead of software emulation.
Goes to: humans who own the constitution.

1. **36 passed, 7 failed, 1 skipped, at commit 1f8a7a4.**  Every test that
   passed under emulation in the part 11 run was run again on the jig.  The
   skip is TST.serial.origin-matches@1: the jig has no upstream Linux clone,
   and the test says so rather than pass.

2. **Six failures, one cause: the clock refused to measure.**  The stopwatch
   showed 0 s, the sieve took "0 ms", and loader.ms, timer.rate,
   share.on-time and share.separate all saw a door that said 0 forever.  The
   loader did what SPEC.timer.1@1 asks: when Linux's quick calibration will
   not vouch for its answer, report 0 rather than guess.  Five tries, five
   refusals, every boot.

3. **Why: every read of the 8254 now crosses two hypervisors.**
   tests/programs/pitprobe.c repeats the first twelve steps of Linux's
   quick_pit_calibrate and prints what it saw.  Three runs each:

   |                               | emulation (Claude's workspace) | the jig (KVM inside Hyper-V) |
   |-------------------------------|--------------------------------|------------------------------|
   | reads per 214.6 us step       | 460 to 1,130                   | 12 to 24                     |
   | cost of one read pair, cycles | about 850, spikes up to 86k    | 66,000 to 129,000            |
   | Linux's test at step 1        | carries on 2 times in 3        | gives up 3 times in 3        |
   | error against limit, cycles   | 21k / 51k, 87k / 48k, 30k / 51k| 134k / 92k, 171k / 92k, 133k / 91k |

   The answer itself was right: a step took about 800,000 cycles, which is
   3.7 GHz, the Ryzen 9 5900X's base clock.  It was too noisy to pass Linux's
   500 parts-per-million bar in Linux's 50 ms.  Emulation was cheap because it
   was not real: the emulated 8254 lives in the same process as the emulated
   processor.  On the jig each read leaves the guest, goes to KVM, and KVM is
   itself a guest of Hyper-V.

4. **The fix is a new version, by the book.**  CMP.timer.tsc-pit@2: the same
   Linux lines, with MAX_QUICK_PIT_MS 50 raised to 150, recorded in its
   origin.toml under a new optional `changed` list (schema/entries.md).  Same
   test, same 500 ppm; on a fast machine it still stops as soon as the error
   is small.  With the jig's numbers it needs about 75 to 95 ms.  @1 is
   untouched.  Chris chose 150 ms over asking the hypervisor (KVM's
   paravirtual clock, 2008) on 2026-10-12, by the history rule: Linus's 2008
   method, given more time, and it works the same on emulation, the jig and
   bare metal.

5. **Three loaders re-pointed.**  CMP.loader@4, @5 and @6 depend on
   CMP.timer.tsc-pit@2 now; their own code changes only in the include path
   and a comment.  Petitions 0004 to 0006 still name @1, which is what they
   asked for, signed; the loaders build @2.  CLAUDE.md's rule ("a change that
   matters is a new version... petitions on the old version keep building what
   they built") is kept for the part and bent for the loaders, on purpose:
   the alternative was leaving the stopwatch red on the only real machine.

6. **New spec and test.**  SPEC.timer.2@1 (draft, Chris's yes pending): with
   reads as slow as the jig's, the part still reports the rate.
   TST.timer.slow-reads@1 checks the door gets past one second.  Its mutation,
   Linux's 50 ms put back, is killed on the jig and survives under emulation,
   where reads are cheap.  That is the first mutation only the jig can kill.

7. **The seventh failure was the test's clock, not the machine.**
   TST.machine.disk-no-sockets@1 ran strace over the sort machine with 10
   seconds to finish.  On the jig it took 61 seconds and 505,888 system calls:
   every disk port access exits to QEMU through KVM_RUN, and strace stops on
   each one.  Under emulation the disk is handled inside QEMU with no system
   call and the whole run is about 2,000 calls.  The limit is now 120
   seconds.  Narrowing strace to network calls (--seccomp-bpf) would be
   faster; deferred until the slow run is a nuisance.

8. **Emulation is not the jig, measured.**  The repo has said so in every
   addendum.  Now there are two numbers for it: about 80 times the cost per
   hardware read, about 250 times the system calls under strace.  Anything that
   touches hardware in a loop is suspect until the jig has run it.

9. **Lines from Linux: 844**, unchanged.  @2 is @1's lines with one number
   different.
