# Findings 0000: what the schema could not express for petition 0000

Source: writing petitions/0000.toml against schema/petition.md.  Each item is
a place where the petition needed to say something and the schema gave it no
way to.  Goes to: humans who own the constitution.  None are resolved.

1. **The purpose has no table.**  The five tables cannot name a purpose, yet
   every petition must carry one.  The schema invented a sixth table, PUR, to
   cope.

2. **Negative requirements cannot be stated.**  No libc, no disk, no
   filesystem, no network appear in the petition only by absence.  Rule 11
   catches extra devices at build time; "this component depends on nothing"
   has no expression at all.

3. **Rules 4, 5 and 6 are unverifiable for unadmitted components.**  They
   read requires, exposes and dependencies from index entries.  Every
   component in 0000 has none.  Rule 1 fails on every line by design, and
   status "draft" cannot distinguish valid-pending-admission from broken.

4. **Review signatures are self-referential.**  The signed field is a
   signature over the petition file, but it lives inside that file.  Each
   seat's signature changes the bytes the next seat signs.  Signatures need a
   canonical form or a home outside the file.

5. **Entry file formats are undefined.**  The schema defines petition fields
   but not what a CAP, CMP, SPEC, TST or SNS entry contains.  The fields
   touches, mechanism, binds, red_when, runner, proves, question, threshold,
   unit, red and consumer were invented to write 0000.  "Defined exactly
   once" has no definition of defining.

6. **Scope has no grammar.**  The value console0 is "table-specific
   narrowing" with no syntax per table, so the referee cannot check it.

7. **Spec clauses can only belong to the primary component.**  Rule 2
   requires it.  But "nothing else on the serial port" is a constraint on
   the kernel and the serial driver, not on hello.  The petition has nowhere
   to put a requirement on a dependency.

8. **One test, two causes.**  The single test goes red whether hello wrote
   the wrong bytes or the kernel chattered.  The referee reports a code and
   nothing else, and cannot name which component failed from a serial diff.

9. **Tests have no time budget.**  "The VM does not halt" is only observable
   with a limit, and a TST has no field for one.  Exit status of PID 1 is
   unobservable from outside the VM without a debug-exit device, which would
   need its own CAP, so "exits with status 0" was dropped from the clause.

10. **No field for the machine or VM definition.**  design.md says each VM
    definition is a petition and rule 11 refers to it, but a petition cannot
    name it.  The sensor's "in the VM" is meaningless without one.

11. **Scaffolding versus pool toolchain.**  Day one builds with the jig's
    compiler.  The toolchain role cannot say "built with scaffolding now,
    rebuild when the bootstrap chain is admitted".  The bloat figure
    design.md says 0000 must produce also has no home, since a sensor needs
    a SPEC clause and this one proves nothing.

12. **References that are not codes.**  Submitter, consumer and seat resolve
    to a keys directory or a prose enum, not a table, so rule 1 does not
    cover them.

13. **Use it or lose it is unmeasurable.**  Tenet 10 revokes unexercised
    grants, but nothing in 0000 records whether a capability was exercised,
    and the brief allowed only one sensor.
