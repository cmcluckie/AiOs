# Findings 0019: the screen

Source: part 16, 2026-10-16, petition 0009 (plan 9.15): Conway's Game of Life
on a screen, in colour, the first thing in AiOs a person can look at instead
of read off a serial port.
Goes to: the architects, and whoever writes the next console.

1. **A screen needs its own BIOS.**  A VGA card comes up blank.  On a real PC
   the card's own BIOS, run by the PC's BIOS, puts it in 80 by 25 text mode and
   loads its font; nothing in Linux does that, because Linux has always found
   the screen already set up.  The machines so far boot through qboot, which
   runs no card's BIOS, and QEMU's screen says "Guest has not initialized the
   display (yet)."  So MACHINE.serial-vga@1 boots through SeaBIOS
   (bios-microvm.bin, shipped with QEMU) with option ROMs on, and the card's
   BIOS (vgabios.bin) does what it did in 1987.  The kernel never touches the
   card's registers.  Both files come with QEMU; whether the jig's QEMU has
   them is something only the jig can say.

2. **One lifted line changed.**  Linux's early_vga_write writes every
   character light grey on black, (0x7 << 8), fixed.  In PART.screen.vga@1
   that is vga_color, so a program's colours reach the screen; origin.toml
   records it under `changed`.  The ANSI-to-VGA colour table is Linux's, from
   vt.c (Copyright 1991, 1992 Linus Torvalds): ANSI red is 1, VGA red is 4.

3. **The first picture was double-spaced.**  The first time Life drew on the
   screen, every row had a blank row under it, and the top line had scrolled
   off.  Linux's early VGA code wraps the moment the 80th character lands, and
   then the newline after it wraps again.  Every terminal since DEC's VT100
   (1978) waits instead: a newline straight after the 80th character just ends
   that line.  The serial terminal did it right; the screen didn't.  The fix
   is ours, in the kernel's console, not in the lifted lines: the screen is
   told about a newline only if the line didn't already end at the edge.  A
   mutation puts the old behaviour back and TST.life.screen@1 goes red.

4. **The cursor is left where the firmware put it.**  The card draws a
   blinking cursor in whatever cell SeaBIOS left it, two rows down.  Moving it
   means writing the card's registers, which CAP.dev.vga@1 says nothing may
   do, so it stays.  The screen check skips lines 13 to 15 of every cell,
   where the cursor is drawn, so a blink can't decide a test.

5. **Pixels catch what bytes can't.**  With Linux's colour table replaced by
   one that takes ANSI numbers as VGA numbers, every byte on the serial port
   is still exactly right (TST.life.colour@1 stays green) and the blue dots
   come out red.  Only TST.life.screen@1, which reads QEMU's picture of the
   screen, cell by cell, goes red.

6. **The referee passed a program it could not read.**  Rule 12 compiles a
   program to read its instructions.  If the compiler refused, the referee
   said nothing and passed it: it had looked at nothing and called that clean.
   Fixed to fail closed; TST.referee.no-hardware@1 now feeds it a file that is
   not C and expects a refusal, and a mutation switches the fix off.

7. **The cheat rule 12 cannot see.**  A program that writes straight to the
   screen's memory at 0xb8000 uses no forbidden instruction; it is an ordinary
   store.  tests/programs/screencheat.c does exactly that, and
   `pool/AGT.referee@1/referee hardware PART.screencheat
   tests/programs/screencheat.c` passes it.  Programs still run with the
   kernel's own power and the first megabyte mapped; closing this is plan
   9.13 (the gate, programs with less power than the kernel), not rule 12.

8. **Not checked yet.**  Everything above ran under software emulation in
   Claude's workspace: 63 passed, 0 failed, 5 skipped; every mutation for the
   new and changed tests caught.  The jig's run is the one that counts.
