# Findings 0011: from KERNAL to kernel

Source: petition 0006, two programs at once, 2026-10-12.  The kernel appears.
Goes to: humans who own the constitution.

1. **The loader grew into the kernel; no separate component.**  Plan 9.6 left
   it open: the next loader growing into a kernel, or a CMP.kernel@1 the loader
   hands off to.  CMP.loader@6 grew.  Through @5 it was a KERNAL in Commodore's
   sense: a table of services at fixed addresses (the door) and one program.
   @6 shares the processor and the memory between programs, which is what a
   kernel is for.  Given one plain program it does exactly what @5 did and
   touches no interrupt controller, no timer and no page table
   (TST.loader.plain-6@1, TST.loader.ladder-6@1).  The name CMP.loader stays
   until Chris decides otherwise.

2. **Preemptive, the Amiga way.**  Chris chose preemptive over cooperative on
   2026-10-12, by the history rule: the Amiga's Exec (Carl Sassenrath, 1985)
   took the processor back on a timer, prioritised round robin.  Ours is plain
   round robin on the 8254's counter 0 at HZ 100, Linux's user-visible tick
   rate.  The test that matters puts the stopwatch next to BYTE's 1981 sieve,
   which never calls the door while it works: the stopwatch keeps every second.
   Mask the tick and the machine becomes cooperative: the stopwatch, first in
   the archive, never gives the processor up and the sieve never runs.  That
   sabotage is caught (TST.share.on-time@1).

3. **Separation the Amiga did not have.**  Exec had no memory protection; any
   program could write anywhere.  Ours gives each program its own page
   directory: its own 8 MiB at 0x400000, the kernel's pages, and nothing else.
   So programs built for any earlier loader, all linked at 0x400000, run side
   by side unchanged, and a program that writes past its own memory takes a
   page fault and is stopped alone (TST.share.separate@1).  The kernel says so
   on the console in the Amiga's format, `Guru Meditation #0000000E.00C00000`:
   the exception number first, as the Amiga did for processor errors, then the
   address it touched, where the Amiga put the task's address.

4. **The hole that is left, on purpose.**  Programs still run at the kernel's
   privilege (ring 0).  The kernel's own pages are mapped writable in every
   directory, and a program could turn paging off.  Closing that needs ring 3,
   and a ring 3 program cannot call the door, which is a table of function
   pointers into the kernel: the door has to become a gate (a software
   interrupt or sysenter).  That is a door change, so it is its own rung.  Every
   program on the ladder would have to be rebuilt, or the old door kept beside
   the new one.  Recorded as a decision for Chris.

5. **A modern processor ignores a 1981 interrupt controller until told
   otherwise.**  With pic=on and pit=on the 8259 was ticking and the processor
   never heard it: qboot leaves the local APIC's LVT0 masked.  Linux's
   init_bsp_APIC sets LVT0 to ExtINT ("virtual wire") when the firmware has
   not, and that, lifted, is what made the first tick arrive.

6. **Two programs, one boot module.**  QEMU's direct boot passes one module.
   The programs travel in a cpio archive, the 1970s Unix format Linux still uses
   for its initramfs, read by Linux's own early reader (lib/earlycpio.c).  The
   builder writes the archive itself in sh (jig/aios newc), so the jig needs no
   cpio tool.

7. **No microsecond clock, again.**  Linux waits udelay(100) after setting up
   the 8259 and slows its port writes with outb_p; both are cut, as the disk
   driver's waits were (findings 0010 #3).  QEMU's 8259 and 8254 need neither.
   Real ones might.  For the bare-metal rung.

8. **Door calls are atomic.**  Every door runs with interrupts off, so a tick
   never lands inside one and two programs' bytes never interleave mid-call.
   Read waits with interrupts on, so a program waiting for a key does not stop
   the others.  Hello and Hanoi run together and both outputs come out whole,
   Hanoi's 15 moves in order (TST.share.all-exit@1).

9. **Lines from Linux: 844**, from 638: the 8259 and APIC setup (78), the tick
   (23), the cpio reader (105, about 30 of them glue).  The kernel's own part,
   ours: loader.c went from 134 lines to 350, plus 67 in isr.S.
