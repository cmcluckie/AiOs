# Findings 0039: Dave's sieve, car 1, and what AiOs lacks to run it

Source: part 24, 2026-11-08.  Dave Plummer's drag race, PlummersSoftwareLLC/
Primes at bd2d51111adb76405cb704b5eb78669591d6f32b, PrimeC/solution_1 (Mike
Koss, April 2021; BSD-3 by the repository's CONTRIBUTING.md), built and run by
out/sieve-car1.sh on the jig, as Chris pasted it.  Goes to: the architects
(Chris and Claude).

1. **One program for all three cars.**  Built on the jig as one static 32-bit
   x86 program: solution_1's sieve.c with its own flags (-Ofast -march=native
   -mtune=native -funroll-all-loops), musl 1.2.4 as jig/libc builds it (84 of
   its source files linked), and AiOs's own 64-bit divide, PART.divide64@1, for
   the __udivmoddi4 musl's printf needs.  sha256 7b53af81d8954337...  The same
   file is meant to run on the jig's Linux, on AiOs with one program, and on
   AiOs with several.

2. **Car 1, the jig's Linux 6.18.55 on a Ryzen 9 5900X, under KVM inside
   Hyper-V: 25,097, 24,924 and 24,797 passes in 5.0 seconds**, sieving to
   1,000,000, every pass checked by the program (its own "mckoss-c830" line).

3. **The Linux calls it makes**, counted by strace over a 1-second run: mmap2
   3,107; munmap 3,105; clock_gettime64 2,979; brk 2; and writev, set_tid_address,
   set_thread_area, ioctl and exit_group once each.  Every pass asks for 64 KiB
   and 4 KiB and gives them back; the clock is read about once a pass
   (clock(), CLOCK_PROCESS_CPUTIME_ID).

4. **Against PART.gate@2, what AiOs has today** (cat, part 20):
   - writev, ioctl, exit_group, set_thread_area, set_tid_address, brk and mmap2
     are there.
   - munmap answers 0 and gives nothing back (gate.c: "the memory stays the
     program's until it exits").  At about 5,000 passes a second and 68 KiB a
     pass, a 64 MiB machine runs out in well under a second.
   - clock_gettime64 (call 403 on i386) is not there.
   - The program has 172 instructions on SSE registers and 4 on AVX ones.  AiOs
     has never switched either on, so the first one stops the program.

5. **Read by Claude: what that makes the work.**  Three fixes to parts AiOs
   already has, each a red test first: the clock call, from the timer (part
   23's part, PART.timer.tsc-pit@2); munmap that gives memory back; SSE and AVX
   switched on, and for the car with several programs, saved and restored when
   the processor changes program.  Which flavor runs a Linux program beside
   others is not checked yet.
