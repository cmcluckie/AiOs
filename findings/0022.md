# Findings 0022: the first petition no person wrote

Source: part 19, 2026-10-18, plan 9.9 and 7.2 to 7.3, and Chris's rulings of the same evening.
Goes to: the architects (Chris and Claude), and whoever builds the quartermaster's draft.
Rewritten in plain English the same night, at Chris's request.

1. **What part 19 is, in one paragraph.**  Until now a person wrote the request
   for every program (the "petition", the form that says what a program needs).
   This time a model writes it.  The program is cat, from Unix Version 7, 1979.
   The model reads cat's source and fills in the form.  The referee (the checker
   with no AI in it) checks the form is a proper form.  The builder then tries
   to build cat, can't, and writes down everything that is missing.  Nothing
   runs.  That list of missing things is what part 20 works from.

2. **What Chris ruled.**  V7's source is read the same way Linux's is: through
   the shared reader, from one fixed version, and nothing is copied into the
   repo.  The builder's stop is a plain list in a file, not a pasted error.

3. **What cat is.**  It prints files.  Give it names and it writes each file out
   in turn; give it nothing and it copies what you type.  The file is
   usr/src/cmd/cat.c, 1,130 bytes.  It comes from the Unix history repo's
   Research-V7 branch, which is one commit (5beb5e90fa2d79c2b5608af7ab5829c182a564b6,
   dated 1979-08-25).  The copy Claude first read over the network matches that
   commit's copy byte for byte.

4. **What is missing, measured.**  Claude tried to build cat the way every part
   here is built.  It stops straight away: it asks for three header files
   (stdio.h, sys/types.h, sys/stat.h) that don't exist here.  Counting what it
   would need from a C library, using the host's headers only to count, gives
   eleven things: fclose, fileno, fopen, fprintf, fstat, getc, putchar, setbuf,
   stderr, stdin and stdout.  AiOs has none of them.  That is the measuring
   stick, not the builder's list: cat's source is not in the repo (nothing from
   V7 is copied in), so the builder cannot compile it in this part.  The
   builder's list is the catalogue numbers the model's petition names that have
   no entry yet (item 14).  So the interesting question for the post is how
   close the model's petition gets to this measured list.

5. **A guess, labelled as one.**  A C library written for Linux will probably
   turn those eleven things into five Linux system calls: open, close, read,
   write and fstat.  AiOs answers read, write and exit today.  The measured list (item 13)
   is longer than this guess.

6. **A problem for later (part 20).**  cat is written in 1979's C: main has no
   return type and the arguments are declared after the brackets.  Parts here are
   built as modern C with warnings counted as errors, and cat won't build that
   way.  GCC has an old setting (gnu89) that accepts it.  Written down now so
   nobody is surprised.

7. **A licence question, also for part 20.**  The V7 branch includes a 2002
   letter from Caldera (the company that then owned the Unix source).  It lets
   anyone use, change and share the code if they keep the copyright notice,
   repeat it in binaries, and (the unusual part) acknowledge Caldera in any
   advertising for the product.  This repo is GPL-2.0-only.  Part 19 only reads
   cat and copies nothing, so it is clear.  When part 20 builds V7's lines into
   something, Chris decides whether the advertising rule fits under GPL-2.0-only,
   probably with someone who knows licences.  Claude is not a lawyer and has
   not decided it.

8. **The plan: four small pieces.**  Each gets a test written first, run to see
   it fail, and only then built.
   (a) **The reader learns V7.**  The reader today answers only from one fixed
   Linux version, and says no to anything not in it.  It gets a second fixed
   source, V7, kept in a new file (jig/v7.pin).  Questions about names and
   callers (which use a different tool) stay Linux-only and say so.
   (b) **A draft step.**  A new script, jig/draft, works like the exam's runner.
   It gives the model the purpose, the form's layout, one finished petition as an
   example, and the reader, and saves the reply.  In tests a saved reply stands
   in for the model, so the tests never spend money.
   (c) **The referee reads the draft.**  `referee petition FILE` checks one file:
   it has the fields, every number has a version and either exists or comes with a
   part not yet admitted, it has not expired.  If the reply isn't a proper form, it
   is refused and nothing is kept.
   (d) **The builder stops with a list.**  When a program can't be built, the
   builder writes out/FLAVOR/missing.txt and exits with its own code meaning
   "stopped, not crashed" (3).  The list is every catalogue number the petitions
   name that has no entry, one to a line with what kind of thing it is, in the same
   order every time.

9. **The rules and tests this adds (drafted for Chris to decide).**
   - SPEC.reader.5 and TST.reader.v7-pin: the reader answers from V7's fixed
     version the same way, and refuses anything not in it.
   - SPEC.draft.1 and TST.draft.parses (the draft step, TOOL.draft@1): a draft is
     either a petition the referee can read, or it is refused and nothing is kept.
   - SPEC.builder.1 and TST.builder.missing-list (the builder, TOOL.builder@1): a build that can't finish
     writes the full list of what's missing, the same every time.
   - SPEC.builder.2 and TST.builder.no-guess: the list holds exactly those
     numbers, none of its own and none left out, and a flavor missing nothing gets
     no list.
   - SPEC.referee.draft and TST.referee.draft: the referee reads a draft petition.
   The builder and the draft step have no catalogue entry yet; this adds two
   scaffold entries, the way the reader and the exam have.  Each test's runner names a script that doesn't exist yet, so each fails now,
   for the right reason.

10. **The purpose is Chris's.**  Every petition needs a purpose that Chris signs.
    Claude's draft for PUR.0011@1: "Print the contents of the files named, or of
    standard input, to the console."  Everything else is the model's job.

12. **Not in part 19.**  The C library, the loader for Linux's program files, the
    system calls and actually running cat (all part 20, item 13), the licence
    decision (before part 20), and fixing the two holes left open in part 18
    (the mechanic).

13. **Measured: the C library and the loader, and parts 20 and 21 become one.**
    Chris's call, after the numbers.  Claude built musl 1.2.4 (a small C
    library, MIT licence) for 32-bit x86 from its source and linked V7 cat
    against it, on a normal Linux computer, not on AiOs.  The result is 41,928
    bytes, 25,007 of them code.  66 pieces of musl go into it, about 2,500 lines
    of the library's source.  It needs a 64-bit divide helper (__udivmoddi4) that
    normally comes from the compiler's own runtime library; the jig has none,
    and a three-line stand-in was used to measure.  Run under strace, printing a
    file asks for 11 different system calls (set_thread_area, set_tid_address,
    statx, open, brk, mmap2, munmap, read, close, writev, exit_group) and copying
    standard input asks for 6.  AiOs answers read, write and exit, plus the four
    AiOs-only numbers.
    What the kernel must newly do: load a Linux program file (cat has four
    sections, starting at 0x08048000); build the stack the library expects
    (arguments, environment, extra facts); set_thread_area, a new entry in the
    processor's segment table that has to be swapped on every program switch when
    programs share; and a table of open files for open, read and close.  The short
    ones: brk and mmap2 on top of alloc, munmap doing nothing, statx answering for
    a few cases, writev as write done twice.  Also needed: the builder allows
    per-program flags (item 6), and musl gets its own pinned source for the
    reader, the way V7 does.
    So the old parts 20 and 21 are one part, part 20, published 2026-11-13, and
    the series ends there.  It has a break in the middle: first musl starts up
    and prints something, then cat prints a file.  If the first half runs long,
    that is where it splits.
    These numbers came from Claude's workspace, not from a file in the repo.
    Part 20 measures them again on the jig, from a file in the repo.

14. **What changed while building (2026-10-19).**  Four things differ from the
    plan above.  (1) The builder's missing list is catalogue numbers, not C
    headers and library functions: it lists every number the petitions name that
    has no catalogue entry (for a fixture draft: PART.cat@1, SPEC.cat.1@1 and
    TST.cat.prints-file@1).  Compiling cat to find the headers is part 20's job,
    once cat's source is lifted into lifted/ with an origin record.  (2) The
    referee needed a new command, `referee petition FILE`, to read one draft
    before it is a flavor; it checks the shape and rules 1, 2 and 9 only.  A
    clause or test number that does not exist yet is accepted when the draft
    lists a part not yet admitted, because they come with it.  (3) The draft step
    is TOOL.draft@1 (jig/draft), named like the tool it is, not "quartermaster",
    which stays the name of the agent it is a scaffold for.  (4) The draft step
    tries once by default; DRAFT_TRIES raises it.
    The tests for all of it use saved replies and a fixture petition written by
    hand, so none of them calls the model or spends anything.  The real draft is
    one call that needs Chris.
