# Findings 0018: the petition is the partition

Source: part 16, 2026-10-16, building plan 5.8, and Chris's question "why would
you even think that's close to what we should have?"
Goes to: the architects (Chris and Claude), and whoever reads the next kernel.

1. **What was wrong, and why.**  Every kernel from loader@2 to @7 was made by
   copying the one before and adding the part the new rung needed.  So each one
   carried everything every earlier kernel had: the editor's kernel had the
   stopwatch's two clocks, the 8259, the tick and the cpio reader in it; the
   sieve's had the disk and the filesystem.  The petitions listed those parts
   only because the kernel dragged them in, and the referee refused four
   petitions for it on its first night (findings 0017 #3).  Claude built it
   that way, reading "petitions add, never swap" as "each kernel stacks on the
   last".  The rule is about petitions.  Nobody decided the bundle; it grew.
   Chris's rule, in his words: if a kernel gets built with a series of
   applications, it has exactly the code their petitions asked for; delete an
   application and its parts go with it.

2. **What was built.**  PART.loader@8: one kernel source, every part behind a
   switch the builder sets from the flavor's petitions, nothing else compiled
   in.  Sharing moved out of the kernel into PART.share@1, unchanged.  The
   clocks and the filesystems now expose the capabilities they provide, so a
   petition that asks to read the time has to name a clock.  Sort, the sieve
   and the editor moved onto it, and their petitions dropped every part they
   never used (decision 0011).  The editor's kernel went from 19,704 bytes to
   11,372; the share flavor's from 19,704 to 15,384; sort's from 11,880 to
   10,988.  The referee, on the same night, at the same commit, before the jig
   ran: 72 lines, 0 FAIL.

3. **The check.**  TST.loader.partition@1 works out, from the petitions and
   the catalogue alone, which parts each kernel on @8 should hold, then looks
   at the functions actually in the built kernel: every named part has its
   functions in, no other part has one.  Two mutations put the bundle back
   (every part on) and take the petitions away (no part on); both go red.

4. **Still ours, not yet a chooser.**  With both clocks in, the kernel asks
   KVM first and times the 8254 if KVM says nothing, the order @7 had.  Plan
   5.8 says a run-time choice between parts needs a chooser the petition asks
   for, lifted from Linux's clock-source selection.  Not done; the share
   flavor is the only one with both clocks, because the stopwatch's petition
   still names both.

5. **What stays.**  loader@5, @6 and @7 are built by nothing now.  Their
   folders stay, because sort, the sieve and the editor were compiled against
   their program formats (door.h and program.ld), which are byte-for-byte the
   same as @8's.  Hello to the stopwatch still boot their own kernels, @1 to
   @4, which already held exactly what each one needs.

6. **Not checked yet.**  Everything above ran under software emulation in
   Claude's workspace: 57 passed, 0 failed, 5 skipped; 18 of the 18 mutations
   for the changed tests caught.  The jig's run is the one that counts.
