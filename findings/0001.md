# Findings 0001: the kernel is not a component

Source: talking through petition 0000 after the machine was written (plan 2.4),
Oct 10, 2026.  Goes to: humans who own the constitution.  Decided the same
evening; the resolutions below are applied in this commit.

1. **The build plan admitted the kernel as a whole and apologised in a
   ledger.**  design.md "Build plan" had hello run as PID 1 under a
   configured Linux kernel, with a bloat figure "near 100 percent" as the
   honest baseline.  That is tenets 1 to 3 with an exception carved out for
   the largest thing in the system.  Even the smallest configuration still
   builds a scheduler, a memory manager, a device model, a logging buffer and
   an in-memory filesystem, none of which any petition names, and "turned
   off" in Kconfig means not compiled this time, not absent from the pool.

2. **One program needs no landlord.**  A kernel's job is sharing one machine
   between tenants that do not trust each other.  Petition 0000 has one
   tenant.  Every line that is present can be attacked whether or not anyone
   asked for it, and a machine that can only do one thing can only be broken
   one way.  The security argument and the purpose argument point the same
   way.

3. **Linux is one program, not a parts bin.**  The ten lines that put a byte
   on a 16550 are wrapped in a few thousand that hold hands with the tty
   layer, the device model, the allocator, locking and the scheduler.
   Lifting a segment means cutting those hands.  design.md "The base" already
   said compose, don't configure; the build plan did not follow it.

4. **Linux carries almost no specs or tests for what we would lift.**  The
   serial driver, the boot path and the process machinery have no unit tests;
   the scheduler has benchmarks.  Every segment lifted arrives naked, and the
   admission door requires us to write its SPEC and its TST.  This is the
   door working as designed, not a side cost, and it is the pressure that
   keeps segments small.

5. **A program that owns the machine is a cardboard box.**  If hello sets up
   the processor, writes to the port and halts, then petition 0001 (write to
   a disk) cannot add to it; it must replace it.  Additive petitions require
   that petition 0000 already separate the loader from the program, and the
   driver from both, so that hello is a tenant even while it is the only one.

6. **Is it still Linux?**  No.  It is segments of Linux, admitted one at a
   time with specs and tests Linux never had, laid so that later petitions
   stack.  The test the constitution actually sets is whether every line
   traces to a petition, and that is the question to keep asking.

## Resolutions

| Finding | Resolution |
| --- | --- |
| 1, 2 | Petition 0000 names no kernel.  CMP.kernel.core, CMP.kernel.serial.8250 and CMP.kernel.initramfs leave the petition unadmitted and are not pursued. |
| 3, 6 | Linux is read, never booted.  Each segment is lifted into its own pool directory with the hands cut; the cut is recorded in the as-built spec.  Rule added to CLAUDE.md. |
| 4 | Every lifted segment arrives with a SPEC and a TST written here.  Rule added to CLAUDE.md; already implied by the index README. |
| 5 | Petition 0000 is three bricks: CMP.loader@1 (takes over from the machine, sets up the processor, runs one program, halts when it exits), CMP.serial.8250@1 (the byte-on-the-wire segment, lifted), and CMP.hello@1 (calls the loader's door, never the hardware).  Rule added to CLAUDE.md. |
| — | A kernel appears only when a petition asks for two things that must share: a second program, a program and a network.  Until then the loader is the whole landlord. |
| — | Findings 0000 #15 (the panic on PID 1 exit) is moot: there is no kernel to panic.  CAP.proc.exit's mechanism reworded. |
| — | design.md "Build plan" and plan section 6 rewritten; plan 7.4 reworded. |
