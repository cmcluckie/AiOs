# Findings 0021: the gate

Source: part 18, 2026-10-18, plan 9.13, and Chris's rulings of the same morning.
Goes to: the architects (Chris and Claude), and whoever reads the next kernel.

1. **What is there already, and what is not.**  PART.share@1 gives each
   program its own page tables, installs an interrupt table, and stops a
   program that faults, alone, with a Guru Meditation line.  It does not run
   programs in ring 3, it gives every program the kernel's own pages from
   1 MiB up (share.c, `low_pt`), and only a kernel built with share has any
   of it: the plain loader has flat segments, no paging and no interrupt
   table.  Findings 0019 #7 says tests/programs/screencheat.c writes to
   0xb8000 and gets through; the first megabyte is not mapped under share,
   so that line, and the words "first megabyte mapped" in 0019 #7, were
   wrong as written (corrected here, 0019 left as signed).  The real hole is
   that a program runs at ring 0 and can reach the ports and the kernel's
   pages.  Claude first told Chris the kernel had no paging and no interrupt
   table; that was true only of the plain loader.

2. **Ruled by Chris, 2026-10-18.**  Paging, not segments: this is a modern
   operating system and it is done the way it is meant to be done, unless the
   other is needed for something else.  Segments could not hide the kernel in
   any case: it sits at 1 MiB, below the programs at 4 MiB, and a segment can
   only cut off the top.  The system calls without a Linux number yet get
   AiOs-only numbers for now, as marked tech debt that has to be removed.

3. **The plan.**  A new part, PART.gate@1, owns the descriptor table with ring 3
   segments, the TSS, the interrupt table, the int 0x80 entry, the fault
   handlers, and the page tables (kernel pages closed to programs, program
   pages open).  PART.share@2 depends on it and keeps only the scheduling and
   the per-program memory; its page-table code moves into the gate, the way
   sharing came out of the loader in part 16.  PART.loader@9 always has the
   gate, so a single program is in ring 3 too.  The programs are not
   recompiled: the table they are handed has the same seven entries in the
   same places, and each now holds a small stub that runs int 0x80.  Before
   anything moves, the tests below are written and shown red; the share
   refactor has to keep TST.share.separate@1 and the ladder green.

4. **The specs and tests, drafted for Chris to decide.**  SPEC.gate.1 to 4;
   TST.gate.screen-refused, port-refused, kernel-refused, int80, ladder and
   debt-listed.  Each test's runner names a script that does not exist yet, so
   each is red now, for the right reason: nothing has been built.  None has a
   mutation yet.

5. **Tech debt.**  A line of source that is there on purpose and has to go is
   marked `TECH-DEBT n` in a comment, with what replaces it and when it goes,
   and is listed here under the same number.  SPEC.gate.4 and
   TST.gate.debt-listed check that the two match.  Nothing else in the repo
   uses the mark.

   TECH-DEBT 1.  The system call numbers 1000 (alloc), 1001 (ms), 1002 (load)
   and 1003 (save) are ours.  Linux's 32-bit x86 numbers stop well short of
   1000, so nothing clashes.  They go when part 20 brings a loader for Linux's
   program files: alloc becomes brk, ms becomes clock_gettime, load and save
   become open, read, write and close.  Until then a Linux program that asks
   for one of those four gets an error, not a guess.

6. **Not decided here.**  Whether the plain loader's single program gets the
   same page-table layout as a shared one (Claude's pick: yes, one layout, so
   there is one thing to test), and whether the screen's memory is ever given
   back to a program (no; the kernel draws, the program asks).
