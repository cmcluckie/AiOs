# Findings 0014: language matters

Source: a conversation, 2026-10-13, not a petition.  Chris's call.
Goes to: humans who own the constitution.

1. **Readers learn the words once.**  The series is read by people who
   remember everything.  A word that shifts under them loses them.  So the
   vocabulary is fixed now, while the project is days old, and changing it
   afterwards is a human-only decision (the decision ledger, plan 3.6).

2. **What changed, old to new.**

   | Old | New | Why |
   | --- | --- | --- |
   | segment | part | "segment" already means x86 memory segmentation, which the nucleus sets up at boot |
   | the centre, the OS | the nucleus | Per Brinch Hansen's word (RC 4000, 1969); "core" collides with processor cores and with CoreOS |
   | the roles around it | agents | the referee, builder, tester, historian, quartermaster, mechanic, committee |
   | CMP, one table for everything | PART, MACHINE, TOOL | "component" was doing two jobs and confused even us |
   | component (for a piece of the nucleus) | part | the nucleus is made of parts; component is now only the word for the three tables together |
   | AiOS | AiOs | the name was always AiOs, lower-case s; Chris corrected it more than once and it was missed.  Parts 1 to 12 went out as AiOS and stay that way |
   | the index | the catalogue | the folder stays index/ (formerly the index), so no published link breaks |
   | code (the name a petition uses for something) | catalogue number | "code" already means source code; the TOML key is still `code` |
   | the door (what a program calls the kernel through) | system call; the whole thing is the system call table | "door" also meant the one way in, a petition; system call is the term Unix has used since 1971 |

3. **The CMP split.**  22 entries became PART (drivers, the kernel versions,
   the cpio library, the programs), 4 became MACHINE (the VM definitions; not
   MACH, which is a famous kernel), 2 became TOOL (the C toolchain and the
   QEMU stand-in, the scaffolds).  Directories moved to match: pool/PART.*,
   pool/MACHINE.*, lifted/PART.*, index/part/, index/machine/, index/tool/.
   263 files rewritten by one script; every test still passes.

4. **Codes are immutable once committed, and these were renamed anyway.**
   schema/petition.md says a code at a version never changes.  Every renamed
   code was a draft: none had a signed admission.  The rule is about admitted
   codes, and no admitted code was touched.  Recorded here so it is not read
   as a precedent for renaming admitted ones.

5. **What breaks.**  Links in parts 5, 6, 9, 10 and 11 as published on
   LinkedIn point at the old CMP directories and now 404.  Chris chose this
   over keeping the old names, on 2026-10-13.  Renaming the index to the
   catalogue would have broken every published part but part 2, so the word
   changed and the folder did not: index/ holds the catalogue.  The GitHub copies of the posts are
   fixed; LinkedIn posts are not edited.  Older findings keep the old words:
   they are the record.

   "Door" keeps one meaning: the one way in, a petition (tenet 2).  Code
   identifiers keep the old word, as the kernel is still PART.loader: door.h,
   struct door, and the test codes TST.loader.door-layout@1 and
   TST.loader.doors-wait@1, because test codes are immutable once committed.
   Spec clauses, as-built specs, capability entries, test descriptions, the
   plan and the README say system call.  The meaning of every clause is
   unchanged; only the word moved.  Findings 0003 recommended keeping
   "door"; that is overruled here.

6. **The guard.**  jig/postcheck fails any post dated after 2026-10-21 that
   uses "segment" or the CMP table, and any post dated after 2026-10-22
   that uses "door" for a system call.  Older posts are the record and are
   not checked for it.
