# Findings 0027: the layered agent, in C

Source: part 22, Chris's design note of 2026-10-27, "AiOs: 3090 director/builder
design note", and his rulings of 2026-10-28.
Goes to: the architects (Chris and Claude).

1. **What it is.**  A second mechanic's bench, built beside the first.  Three
   layers, each seeing only a short note from the layer below, so no conversation
   grows past what the card holds: strategic (Chris and Claude) writes a part
   plan; a director, one per part, on the 3090 by default, turns it into jobs;
   builders, each starting from nothing, do one job each.  The program, not a
   model, runs the tests on the jig and writes the result note the director
   reads.  The director never sees a builder's transcript, and a builder never
   sees its own last try.

2. **Ruled by Chris, 2026-10-28.**  (a) Built now, in part 22, not a new article.
   (b) A real program in C, in its own top-level folder, agent/, running in WSL2
   beside Ollama.  The jig only runs tests: the agent reaches it over SSH, sends a
   job's files, and gets the test output back.  Nothing new goes on the jig.
   (c) No LangGraph, no LiteLLM.  The agent logic is ported from Chris's own
   CivicCanada (C:\Code\CivicInfo, C#): the ReAct loop, the split of system and
   user prompts, and the handling of context and history, with its check that
   folding kept what matters.  The logic, not the language, and the origin is
   credited the way lifted/ credits Linux.  (d) jig/fix is not touched from
   a8bfd5a on: it is the control.  (e) The budget is one value Chris sets,
   starting at $40 a month.  (f) Tests for the agent itself, written to fail.
   (g) The race: all three exam parts (the serial driver, the timer, the
   screen) on both benches, the same model on the card, the same pinned source,
   the same caps.  Graded on ceiling, not cost: which bench, peak context used,
   and whether a run ended by passing, by running out of room, or stuck.
   Dollars logged, not graded.

3. **What comes from CivicCanada, as ideas.**  The ReAct loop (reason, call a
   tool, read the answer, repeat), with a required reason on every tool call and
   a cap on tool answers (both already on the old bench, decision 0092); the
   system prompt for the role and rules, the user prompt for the one job; the
   history folded when long, with a check that the fold kept what matters.
   CivicCanada's history is chat turns; the director's is result notes, so what
   the fold must keep is decided here, not taken over: the part plan, every job's
   one-line status, the last three result notes whole.

4. **What is new, one module each, each with a test written to fail first.**
   The result note, from the jig's test output.  The part plan reader.  The
   builder loop.  The director loop.  The stuck rule and the caps.  The question
   note and the pause.  The SSH step to the jig.  The budget ledger
   (runs/budget.md) and the check before a paid call.  The director's log and
   its compaction, and search_log.  The prompt library, its versions and the
   prompt trial.  The track-record check.  The new scorecard columns.

5. **Borrowed, not written.**  libcurl for HTTP to Ollama and Bedrock; it signs
   Bedrock's requests itself (CURLOPT_AWS_SIGV4), as curl does for jig/model
   today.  cJSON for JSON: MIT, one C file and its header, widely used; kept in
   the repo with an origin record, not installed.  Both run in WSL, not on the
   jig, and have rows in design.md's tool table with how they leave.

6. **What is known before it runs.**  The 3090 has made one fix, waits
   (TECH-DEBT 2), on the old bench, twice, on try 3 (findings 0026 item 11): 21
   calls without the required reason, 14 with it, against Sonnet's 12.  It has
   not sat any exam part.  The design note said it passed the timer; it passed
   waits.  So the race's first exam runs are the 3090's first track record there.

7. **The mechanic rule.**  Decision 0057 dropped "may not share a model" from
   design.md; CLAUDE.md still said "never share a model or prompt".  Both now say
   the mechanic never shares a prompt with the director or any builder, and the
   scorecard shows when the mechanic and the builder ran on the same model,
   because the same model checking its own work tends to share its blind spots.

8. **Still open.**  The flat rate per band for each part's budget share, set from
   the first runs.  Whether the exam's runner (jig/sit) becomes the program's
   outer loop or the program replaces it for the race.
