# Findings 0007: the runner, and what the mutations found

Source: plan 4.1 to 4.3, the test runner and the mutation script, 2026-10-11.
Goes to: humans who own the constitution.

1. **Every test with a runner passes; none of them had been run by anything
   but a person until today.**  `sh jig/test` runs all 17 tests and writes
   tests/results.txt.  All 17 pass, under software emulation (tcg) in a
   container, not on the jig and not under KVM.  That is evidence, not the
   done-when, until the jig exists (plan 2).

2. **Expected outputs are files, not programs.**  The references for Hanoi,
   Life and the calculator are Python and Python is not admitted on the jig.
   So each reference was run once on a normal computer and its output saved in
   tests/expected/; the runner only compares bytes.  The references stay in
   tests/fixtures/ so anyone can regenerate and check.  Life's reference was
   written from the rules, not translated from life.c, and agrees on all 1992
   bytes; it is still the same author's understanding twice (see the article).

3. **The serial driver can stop waiting for the chip and nothing notices.**
   Mutation: the loop in serial8250_putc that waits for "transmit holding
   register empty" before each byte is skipped.  Every test stays green,
   because QEMU's 16550 is always ready.  On a real 16550 bytes would be lost.
   No spec clause says the driver waits.  Asks for: a human-written clause on
   CMP.serial.8250 ("before each byte goes to the transmit register, the line
   status register has been read with THRE set"), and a test for it: jig/test
   can already capture QEMU's register trace (`trace` kind; loader.halts@1
   uses it), so the test is a dozen lines of checking.

4. **Init is still untestable on this machine.**  Mutation: init sets 5 data
   bits instead of 8.  Every test stays green; QEMU ignores the line format.
   Findings 0002 #7 said so; now a mutation proves it.  The same register
   trace could check the nine init writes exactly, if a clause asks for them.

5. **loader.read@1 cannot see a read door that over-reports.**  Mutation: the
   read door claims one byte more than it received.  The calculator asks for
   one byte at a time, so its transcript never shows it, and loader.read@1 is
   built on that transcript.  serial.receive-order@1 does catch it: its echo
   probe asks for 256 bytes at a time.  The clause (SPEC.loader.7@1, "never
   more") is covered, but by the other test.  Asks for: loader.read@2, bound to
   the echo probe, when someone revises it.

6. **loader.same-binary@1 has no mutation.**  Both flavors build the loader
   from the same source, so no single edit makes them differ; the test guards
   the build, not the code.  It would catch a non-reproducible build (plan 5.2),
   which is the point of it.  Recorded so the zero in its `mutations` field is
   not mistaken for neglect.

7. **Three tests share one boot.**  hello.exact-bytes@1, hello.silent-boot@1
   and loader.runs-program@1 all pass on the same 14-byte capture: the whole
   serial output from power-on to halt is exactly hello's bytes, which proves
   all three clauses at once.  Not a problem; noted so nobody counts them as
   three independent pieces of evidence.

8. **The machine forces kvmvapic even under tcg.**  The device tree of a paused
   machine has 13 devices: the serial port, the ISA bridge, the I/O APIC,
   fw_cfg, kvmvapic and eight empty virtio-mmio transports.  All on
   SPEC.machine.1@1's list.  strace saw about a thousand system calls from QEMU
   start to exit and none of them touched the network.

9. **jig/build.sh and jig/build-0000.sh are dead.**  They predate jig/aios and
   still point at pool/CMP.serial.8250@1, which moved to lifted/ in part 4, so
   they no longer build.  Nothing calls them.  Asks for: removal.

10. **The observation flags need a stand-in, not a change.**  Committed
    components never change, so jig/test does not edit machine.sh to add
    QEMU's register trace or a monitor.  It puts a stand-in for
    qemu-system-x86_64 first on PATH that adds those flags and runs the real
    one.  The machine under test is otherwise the committed one, byte for byte.

11. **Plan 4.3's done-when, run.**  The five mutations of hello the plan names
    (wrong byte, missing newline, extra write, no exit, exit before write) are
    all caught.  With the byte comparison removed from jig/test, four of the
    five survive and one is still caught: "no exit" never halts, and the
    runner's own time limit turns that red whatever the comparison says.  The
    plan said 0 of 5; 1 of 5 is the right answer, for that reason.

12. **4.1's done-when, run.**  The runner goes red on a machine that never
    halts (the alloc-refuses mutation: the walk never ends, red at the 10 s
    limit) and on a loader that prints a byte of its own before the program
    (the silent-boot mutation: 15 bytes where 14 were expected).
