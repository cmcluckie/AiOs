# Findings 0023: cat prints a file

Source: part 20, 2026-10-20, plan 9.16, findings 0022 items 7 and 13, decision 0037.
Goes to: the architects (Chris and Claude).
Part 20 is the last part of the series.  It goes out 2026-11-13.

1. **What part 20 is, in one paragraph.**  At the end of part 19 a model had
   written the request for cat, and the builder had stopped with a list of what
   was missing.  Part 20 fills the list in and runs it: a small C library
   (musl), a kernel that can load a normal Linux program file, the system calls
   that program asks for, and Berkeley's cat printing a file from the disk.  It
   has a break in the middle: first musl starts up and prints something, then
   cat prints a file.

2. **Which cat (decision 0037).**  Not V7's: its 2002 licence asks for credit in
   advertising, which GPL-2.0-only does not allow.  Instead cat from 4.4BSD-Lite,
   in the same Unix history repo.  Two releases have it.  Lite1 (tag
   BSD-4_4_Lite1, commit 36708fa95524a270678609988c1071a60c3bd96b) has cat.c
   version 8.1 of 1993-07-19, 251 lines.  Lite2 (tag BSD-4_4_Lite2, commit
   bbae9de38e2ef13d199fe38f3ad2b50c514d5970) has version 8.2 of 1995-04-27, 252
   lines; it differs in three lines (getopt's end compared to -1 instead of EOF,
   a `default:` added to the option switch, err(1, NULL) instead of err(1, "")).
   Both files still print the advertising clause in their header.  Berkeley's
   letter of 1999-07-22 deleted it; the lift keeps the header as it is, as the
   rule for lifted/ says, and its origin record names the letter.  The part 19
   article says "Berkeley's 1994 release", which is Lite1.  Chris decides which.

3. **A bug from 1995, found by measuring.**  In both releases cat declares
   `rval`, the exit status, and never sets it.  A file that cannot be opened is
   reported ("cat: nope: No such file or directory") and cat still exits 0, which
   says it worked.  Later BSDs set it to 1.  The model's petition in part 19 asked
   for a test that a missing file is an error (TST.cat.missing-file-error@1).
   Written the way the series writes tests, that test goes red on Berkeley's own
   code.  Chris decides what happens then: lift it as it is and fix it in a
   separate change recorded in the as-built spec, or decide the test asks for
   too much.

4. **Measured, in Claude's workspace (not yet from a file in the repo).**
   Lite2's cat, built against musl 1.2.4 for 32-bit x86, static, on a normal
   Linux computer: 51,620 bytes, 33,312 of code and data, 80 pieces of musl.
   It does not build as it is.  It needs four things that BSD's own headers gave
   it and musl does not: `__P(x)` (a 1980s macro for function prototypes),
   `u_int` (which BSD's sys/param.h brought in through sys/types.h), the BSD
   names switched on (_BSD_SOURCE), and the older C dialect (-std=gnu89).  The
   64-bit divide helper from findings 0022 is still needed.  Under strace,
   printing a file asks for ten different system calls: set_thread_area,
   set_tid_address, statx, open, brk, mmap2, read, write, close, exit_group.
   Copying standard input asks for nine (no open).  With -v (show unprintable
   characters) it uses stdio instead and adds ioctl, munmap and writev.  Part 20
   measures it again on the jig, from a file in the repo, before anything is
   built.

5. **The pieces, each with a test written first and seen to fail.**
   (a) **The reader learns Berkeley.**  A third pinned source (jig/bsd.pin),
   read the way V7 is.
   (b) **The model drafts again.**  Petition 0013 from Berkeley's cat, by the
   same draft step, recorded the same way.  Petition 0012 stays as the record of
   what the model wrote from V7.
   (c) **musl, pinned and lifted.**  MIT licence, compatible with GPL-2.0.
   (d) **The builder learns per-program flags** (findings 0022 item 6): the four
   above, written in the program's catalogue entry, not in the builder.
   (e) **A kernel that loads a Linux program file**: read its header, put its
   pieces where it says, build the starting stack musl expects (arguments,
   environment, a few facts about the machine), and start it in ring 3 through
   the gate.
   (f) **The system calls in item 4**, at Linux's numbers, each as small as cat
   needs and no more, each refusing what it does not do.  This retires
   TECH-DEBT 1 for every call cat uses.
   (g) **cat prints a file**: a file put on the disk at build time, printed
   byte for byte on the console, and the missing-file test from item 3.

7. **What Chris decides before building.**  (1) Lite1 or Lite2 (item 2).
   (2) What happens when the missing-file test goes red on Berkeley's code

8. **What Chris ruled (2026-10-20, decision 0038).**  (1) Lite1, 1994: the
   original release, and what the part 19 article already says.  The numbers in
   item 4 were taken from Lite2, three lines apart; the jig measures Lite1.
   (2) The missing-file test goes red on Berkeley's code as lifted, untouched;
   then it is fixed in its own change, the way later BSDs fixed it, and the fix
   is recorded in the as-built spec.  (3) Only the pieces of musl cat links,
   each recorded.  (4) Petition 0013 supersedes 0012; 0012 stays in the repo as
   the record of the V7 draft.

9. **Measured on the jig, and lifted (2026-10-20).**  jig/libc built musl 1.2.4
   from its pin on the jig, and linked Lite1's cat against it with the divide
   helper (PART.divide64@1): 82 source files, the list in
   findings/0023-pieces.txt, the same as the workspace's.  Those 82 files are
   3,472 lines.  They do not compile without their headers: with the headers
   they and cat include, the four inputs to musl's generated headers and
   musl's COPYRIGHT, the lift is 174 files and 15,253 lines, 11,008 of them
   headers (lifted/PART.libc.musl@1, decision 0045).  Everything lifted from
   Linux in parts 1 to 19 is 1,102 lines of code; this is 11,869 lines of code
   (no blanks, no comments) in the .c and .h files.  Berkeley's cat.c is
   lifted beside it, 251 lines, 199 of code (lifted/PART.cat@1).  With cat's
   catalogue entry in place, the referee's rule 6 now names PART.libc.musl@1
   as depended on and not listed in petition 0013: the C library the model
   never asked for, caught by a rule.

10. **The plan for running cat, and what Chris ruled (2026-10-20, decision 0046).**
    New versions on top of the old ones, so every earlier program runs untouched:
    PART.loader@10 and PART.gate@2.  (a) The loader takes a normal Linux program
    file (32-bit ELF, static, not position-independent): it puts each loadable
    piece where the file says, zeroes the rest, and builds the starting stack musl
    expects (the arguments, an empty environment, and the facts musl reads: where
    the program's headers are, the page size, the entry point, 16 bytes for
    AT_RANDOM).  (b) The gate answers, at Linux's 386 numbers, the system calls cat
    makes (item 4), each as small as cat needs, each refusing the rest: open,
    close, read, write, writev, brk, mmap2, munmap, set_thread_area,
    set_tid_address, statx, ioctl, exit_group.  (c) The builder builds musl from
    lifted/, cat with its flags, and links them as a normal Linux toolchain would.
    (d) Tests first: cat copying what is typed (the halfway point: musl starts up
    on AiOs), cat printing a file, cat printing two, and the missing-file test that
    goes red on Berkeley's bug.
    Chris ruled: cat runs at Linux's own address, linked as Linux links it
    (0x08048000), so AiOs runs a normal Linux program file as it is; its arguments
    come from the kernel command line, the way Linux's first program gets them;
    AT_RANDOM's 16 bytes come from the processor's cycle counter and the spec says
    plainly they are not random; cat opens files read-only from the Minix disk
    AiOs already reads, and anything else is refused.

11. **The start files (2026-10-20).**  The first lift missed musl's three start
    files, crt1, crti and crtn: the code that runs before main.  jig/libc pieces
    read only what the linker took out of the library's archive, and the start
    files are linked beside the archive, never from it, so the map never named
    them.  They are lifted now with the one header crt1 takes its _start from
    (arch/i386/crt_arch.h): 178 files, 15,304 lines.  jig/libc pieces lists them
    by name, so its list for a program is now complete; the expected list for
    tests/fixtures/libc/hello.c grows by those three (decision 0047).

12. **What ran, in Claude's workspace (2026-10-20), and what is still red.**
    Under software emulation (QEMU without KVM, not the jig), with PART.loader@10,
    PART.gate@2 and MACHINE.serial-disk@2: Berkeley's cat, built against musl from
    lifted/, starts as a normal Linux program file and copies what is typed until
    Ctrl+D (the halfway point: musl starts up on AiOs); prints a file from the
    Minix disk, two files in order, and a 5,000-byte file whole; and the probe
    that asks each Linux call for something it does not do is refused every time
    with Linux's own error number.  Asked for a file that is not there, it says
    "cat: /none: No such file or directory", prints the next file and exits 0:
    Berkeley's 1995 bug, and TST.cat.missing-file@1 is red, as decision 0038 said
    it would be.  It stays red in this change; the fix is its own.
    Things that came up: (a) AiOs had no end of input for the console, so Ctrl+D
    ends it, as at the start of a line on a Unix terminal; (b) nothing outside the
    machine could see a program's exit status, so the gate says "exit N" when a
    Linux program ends, which is what shows the bug; (c) one deliberate breakage
    survived: telling musl its program headers are 1 MiB from where they are does
    not stop it, because it only looks there for thread storage cat does not have,
    so that mutation was replaced by starting the program one byte past its entry;
    (d) TECH-DEBT 1 is not retired: cat uses none of the AiOs-only numbers, and the
    programs that do still run unchanged under the new kernel; (e) TECH-DEBT 4 is
    new: AT_RANDOM's 16 bytes are the cycle counter.
    The model's petition could not be built as it was.  Petition 0014 (Chris's,
    superseding 0013) keeps its purpose, its five capabilities and their reasons,
    and its three tests, and changes six things: the kernel (PART.loader@5, which
    cannot load a Linux program file, to PART.loader@10 with PART.gate@2); the C
    library and divide helper it never named (PART.libc.musl@1, PART.divide64@1);
    every "admitted = true" it claimed, to false; the file system it named
    (PART.fs.minix@1, which cannot read the files the newer one writes, to @2,
    with the disk driver and CAP.dev.disk@1 it needs); the machine (to
    MACHINE.serial-disk@2, for the command line) with CAP.dev.serial@1 and
    CAP.cpu.ring3@1; and two more tests, a file bigger than cat's buffer and the
    missing file.  All of the referee's rules pass on 0014.
