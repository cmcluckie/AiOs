# Findings 0010: a disk, and the filesystem Linux started on

Source: petition 0005, save the sorted output, 2026-10-12.  First storage.
Goes to: humans who own the constitution.

1. **The history rule chose both parts.**  Chris added the rule on
   2026-10-12 (CLAUDE.md, How we work): when options would each do the job,
   default to the one with the history.  The disk is IDE, whose registers go
   back to the PC/AT's disk controller (1984), not virtio-blk; the filesystem
   is the original Minix (version 1, 14-character names, magic 0x137F), not
   FAT or ext2.  It is roughly the machine Linux was written on in 1991.
   fs/minix/bitmap.c still opens "Copyright (C) 1991, 1992  Linus Torvalds".
   Both were also the smaller lift: Linux's virtio code is about 7,000 lines,
   most of it machinery shared by every virtio device.

2. **The first expensive lift.**  fs/minix is about 2,400 lines and holds
   hands with Linux's shared file machinery over 200 times: struct inode,
   super_block, dentry, folios, buffer heads, the page cache, mark_*_dirty, two
   locks.  We took the Minix logic (where the bitmaps and inodes live, find a
   free bit, find or add a name, which zone holds a block) and rewrote the
   edges: every block is read, changed and written straight back.  344 lines,
   about 120 of them our glue.  The IDE driver is 122 lines from libata, with
   struct ata_port and the PIO state machine cut down to "wait, check, move
   512 bytes".  Lines from Linux: 638, from 172.  Counted the way the 57 was.

3. **This machine cannot tell time, so the disk driver never tries.**  Every
   wait in libata is timed: ata_sff_busy_wait polls a thousand times with
   udelay(10) between (10 ms), and ata_sff_pause waits 400 ns.  The sort
   machine has no 8254 (one new thing per rung), and counting loops instead
   would be the turbo bug from part 9.  So the driver waits on the drive's
   busy bit for as long as it takes; a status of 0xff (nobody on the bus)
   still ends the wait.  A real drive that never answers would hang the
   machine, and a real drive wants the 400 ns.  Recorded for the bare-metal
   rung (plan 11.6), which will have a clock.

4. **The disk is touched only when a program asks.**  The loader does not
   mount anything at boot.  TST.loader.doors-wait@1 boots hello under
   loader@5 on the disk machine with QEMU's IDE trace on and sees no command
   at all; the mutation that mounts at boot is caught.  On a machine with no
   disk both doors say -1 and sort says it could not save (TST.disk.no-disk@1).

5. **An outside opinion on the disk.**  TST.fs.fsck-clean@1 runs fsck.minix
   from util-linux, a checker nobody here wrote, after sort saves.  It finds
   the disk clean and lists one file, /sorted.  Three sabotages to the
   filesystem (a zone not marked busy, a directory that forgets it grew, an
   inode with no links) are caught by it, not by our own reader.  During the
   build a Python reader, run once in Claude's workspace and not on the jig,
   also agreed: inode 2, mode 100644, 74 bytes, one link, zone 16.

6. **The flush no test can see.**  minix_save ends by asking the drive to
   write its own cache out (ATA FLUSH CACHE).  Take that away and every test
   stays green: QEMU writes the disk file straight through.  On a real drive
   with its write cache on, a power cut just after save could lose the file.
   Written down as a known survivor in tests/mutations.txt, like the serial
   driver's THRE wait was in findings 0007.

7. **Files are dated 1 January 1970.**  The machine has no clock of day (plan
   9.12), so new inodes get time 0.  mkfs.minix dated the root directory with
   the host's clock when it made the disk.

8. **What it cannot do, on purpose.**  Files up to seven blocks (7 KiB, the
   inode's direct zones; indirect zones were cut).  The root directory only.
   No overwrite, no delete, no rename.  A save that fails halfway leaves the
   bits it set marked busy; fsck would report them, and no test makes a save
   fail halfway yet.

9. **The machine formats its own disk.**  If $AIOS_DISK (default
   out/disk.minix) does not exist, machine.sh makes an empty 1 MiB Minix v1
   disk with mkfs.minix, the way a disk came formatted from the shop.
   mkfs.minix and fsck.minix have a row in the tool table (design.md).

10. **The ladder holds.**  Hello, Hanoi, Life and the calculator, each built
    for its own loader, run byte-identical under loader@5 on the disk machine
    (TST.loader.ladder-5@1).  The stopwatch is not on the ladder: it never
    halts, and the disk machine has no timer for it to read.
