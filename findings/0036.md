# Findings 0036: the timer, one number from green

Source: part 23, the timer on the layered agent at b1e1f10 with decision 0114's
fixes, agent/plans/timer.toml, run 2026-11-07 21:37 to 2026-11-08 01:37; then
its best file put on the jig by hand, 2026-11-08.  Every number is from the
builders' logs under out/agent/timer/jobs/ and the jig's output Chris pasted.
Goes to: the architects (Chris and Claude).

1. **The run: red, out of time.**  Three lifters, 240 minutes.  timer-1: 8
   hand-ins, 2 that did not build, 6 that read 0.  timer-2: 10, 7 that read 0
   and 3 that counted too fast (18,000, 36,500 and 34,000 ms against the host's
   9,730 to 9,924).  timer-3, started from timer-2's file: its first three
   hand-ins were that file's score, 34,000 ms against 9,924, then 1 that did not
   build, and the part's 240 minutes ran out at its call 31.

2. **What decision 0114's fixes did.**  Starting from the last file worked:
   timer-3 began where timer-2 ended instead of at "did not build".  Showing the
   tests half worked: no lifter searched Linux for a test's name, but four reads
   were list . looking for door.h, which tests/programs/msprobe.c includes and
   the lifter is not shown.  Keeping the director to facts a note shows did not
   work: its hint to timer-3 said not to assume the 8254 runs at a particular
   frequency.  It does, 1,193,182 Hz, and that number is in the lifter's file.

3. **timer-2's last file is right for an 8254 that answers at the usual speed.**
   It is a lift of Linux's quick_pit_calibrate, with pit_expect_msb and
   pit_verify_msb, and its own 64-bit divide.  In Claude's container, under
   emulation, it passes TST.timer.rate@1 (drift 1 ms per 10 s) and
   TST.timer.slow-reads@1 as written.

4. **On the jig it fails by one number.**  Chris ran it on the jig at HEAD both
   ways: as written, TST.timer.rate@1 failed ("door counted 34000 ms while the
   host counted 9924 ms") and slow-reads passed; with MAX_QUICK_PIT_MS 50 made
   150, both passed ("door 9500 ms, host 9500 ms: drift 0 ms per 10 s").  50 is
   Linux's number.  150 is the hand lift's one change from Linux, made because
   under KVM inside Hyper-V one read of the 8254 costs about 67,000 counter
   cycles, not 850 (findings 0012; the hand lift's own comment).  Nothing a
   lifter is shown says that about the jig.

5. **Read by Claude: what it means.**  The 3090 lifted the timer faithfully.  It
   did not pass by itself: the 150 was put in by hand, from what the repo
   already knew about the jig.  The difference between its file and a pass is a
   fact about the machine the tests run on, not about Linux or the lift.  An
   earlier claim of Claude's, the same day, that this file left out two lines of
   pit_expect_msb was wrong: Claude's own filter for reading it had dropped
   every line starting with "*".
