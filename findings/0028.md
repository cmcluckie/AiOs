# Findings 0028: Rust by default

Source: part 22, Chris's ruling of 2026-10-29, after the agent switched to Rust
(findings 0027 item 9) and decision 0095 set the default out as its own question.
Goes to: the architects (Chris and Claude).

1. **Ruled by Chris, 2026-10-29.**  Rust is the default language for AiOs.
   Default, not rule: every new piece starts in Rust, and C is allowed when one
   of these applies, written in the petition.  (1) It was lifted from Linux;
   lifted/ stays in the language it was written in, always.  (2) It links
   straight against a lifted C part and a Rust boundary would cost more than it
   saves (a tiny shim, a struct layout that has to match, an interrupt entry);
   the petition says which lifted part and why the boundary is worse.  (3) The
   jig's toolchain cannot build Rust for the target yet; then C until it can, and
   the piece is marked for Rust.  (4) Any other reason, written in the petition,
   that Chris accepts.  Tenet 11 in design.md (decision 0097).

2. **Why Rust.**  Memory safety where untrusted input is handled: the agent
   reads model output, and the cold review of its C version found a path the
   model chose writing outside the builder's folder (findings 0027 item 9).
   Rust was already slotted: design.md has had PART.editor@2 as the editor in
   Rust since the ladder was planned.  The agent is the first thing the default
   applies to.

3. **C was first.**  Every part and agent in the pool so far is C, and the
   series has told a C story: the referee rewritten from shell into C, the
   loader grown one system call a rung, the ladder's programs.  None of it is
   rewritten for this ruling.

4. **The jig.**  The jig is scripting, and it is temporary.  When a job moves off
   the jig into an agent, it starts in Rust unless a reason above applies.  What
   already moved off the jig into C without a reason is marked for Rust: a
   record naming the file, what it does, why it is C, and that Rust is the
   target.  It is rewritten when it is next touched for its own reasons, or when
   a petition says so.

5. **pool/, file by file, on 2026-10-29.**  Every C file in pool/ and the reason
   that covers it.  The assembly (start.S, isr.S, gate_entry.S, gate_user.S) is
   neither C nor Rust and stays assembly: it is boot code, interrupt entry and
   the jump to ring 3, which no language above it can write.

   | File | What it does | Reason |
   |---|---|---|
   | PART.loader@1 to @10, loader.c, door.h, kernel.h | the kernel: boots, the system calls, loads programs | 2: calls the lifted serial driver (all), and the timers, disk, Minix filesystem, PIC, tick and cpio (@4 to @7), through their C structs and functions |
   | PART.share@1, @2, share.c, share.h | two programs at once: page tables per program, the scheduler | 2: the lifted PIC, tick and cpio |
   | PART.divide64@1, divide64.c | the 64-by-64 divide helper the compiler calls | 2: the lifted musl calls it by the C name the compiler gives it, __udivmoddi4, with the C calling convention |
   | PART.gate@1, @2, gate.c, gate.h | the descriptor table, TSS, interrupt table, int 0x80 entry, fault handlers and kernel page tables | 3, marked for Rust: no lifted part, so only the toolchain keeps it C |
   | AGT.referee@1, referee.c | the referee: reads petitions, decides, no model | 3, marked for Rust, and first in line: it reads input it must not trust |
   | PART.editor@1, editor.c | the ladder's Notepad | 3, marked for Rust: design.md already names PART.editor@2 as its Rust version |
   | PART.hello@1, hanoi@1, life@1, life@2, calc@1, stopwatch@1, sort@1, sieve@1 | the ladder's programs | 3, marked for Rust: they reach the kernel only through the door, our own ABI, not a lifted part |

6. **Reason 3 covers everything today.**  The jig has no Rust toolchain at all,
   for the target or for itself, so nothing in pool/ is C without a reason, and
   there is nothing to mark as debt without one.  That makes reason 3 a blanket
   until the jig can build Rust.  The pieces marked for Rust in item 5 are the
   ones it is hiding: they would be debt the day the jig builds Rust.  Getting a
   Rust toolchain onto the jig for the target is a row in the tool table first,
   and its own petition.

7. **Marked for Rust, the records.**  Each is a piece whose only reason for C is
   reason 3.  None is rewritten now.

   - **R1.**  pool/AGT.referee@1/referee.c.  The referee: reads petitions and
     the catalogue and decides.  C because the jig cannot build Rust.  Rust is
     the target, first, since it handles input it must not trust.
   - **R2.**  pool/PART.gate@1/gate.c, gate.h and pool/PART.gate@2/gate.c,
     gate.h.  The gate: descriptor tables, TSS, interrupt table, system call
     entry, fault handlers, kernel page tables.  C because the jig cannot build
     Rust for the target.  Rust is the target; its assembly stays assembly.
   - **R3.**  pool/PART.editor@1/editor.c.  The ladder's Notepad.  C because the
     jig cannot build Rust for the target.  Rust is the target, as
     PART.editor@2, already in design.md.
   - **R4.**  pool/PART.hello@1, hanoi@1, life@1, life@2, calc@1, stopwatch@1,
     sort@1 and sieve@1.  The ladder's programs.  C because the jig cannot build
     Rust for the target.  Rust is the target.  Each is a finished rung, so
     "next touched" may be never, and that is fine: an old rung keeps building
     what it built.
