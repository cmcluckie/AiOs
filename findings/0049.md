# Findings 0049: car 3's kernel could not share

Source: part 24, 2026-11-25, out/car3.sh on the jig at 40ce2ee, and the builder
run in Claude's workspace on the same commit.
Goes to: the architects (Chris and Claude).

1. **What car 3 did.**  flavors/dragshare.toml (petitions 0004, 0006, 0015)
   built with exit 0: "PART.loader@10 + PART.stopwatch@1 + PART.sieve@1 +
   PART.drag@1 (ELF)".  Booted on the jig for 15 seconds, it printed nothing,
   and the machine said nothing.  TST.gate.drag-shares@1: "it never showed
   00:00".

2. **Why.**  The kernel's parts (out/dragshare/kernel-parts.txt): PART.gate@2,
   PART.serial.8250@2 and the two timers.  No PART.share, no PART.irq.pic, no
   PART.timer.pit-tick, no PART.archive.cpio: a kernel for one program, handed
   three.  Petition 0015 asks for PART.loader@10, which depends on the serial
   port and the gate alone; petition 0006 asks for PART.share@1, which
   PART.loader@10 does not build with (it builds with PART.share@2).  The
   builder kept the newest kernel and left the sharing parts out without a
   word.

3. **The fix: a petition added, none swapped.**  Petition 0011, the gate on the
   sharing kernel (gateshare, part 18), asks for PART.share@2.  With it the
   flavor's kernel is PART.loader@10 with PART.gate@2, PART.share@2,
   PART.irq.pic@1, PART.timer.pit-tick@1 and PART.archive.cpio@1 (built in the
   workspace; not booted there: under software emulation the sharing flavors
   print nothing, share too, so only the jig can say).

4. **A hole in the builder.**  A flavor with more programs than its kernel can
   run is meant to be refused (rule 19, "flavor both needs 2 programs on one
   machine").  This one was built, because PART.loader@10 lists PART.share@2
   under builds_with, though the flavor never asked for it.  Rule 19 should
   ask what the kernel was built with, not what it could be.  Not fixed here.
