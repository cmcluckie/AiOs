# Findings 0020: the exam's tools

Source: part 17, 2026-10-17, plan 7.0 and the exam for the quartermaster.
Goes to: the architects, and whoever writes the quartermaster.

1. **The reader is a script and a catalogue entry that is not a part.**  Findings
   0015 promised it a name when it was built.  It is built (jig/reader, shell,
   plan 7.0's mechanical half), and the name is still open: today it is
   TOOL.reader@1, a scaffold the jig lends, because that is what a jig script
   that leaves with the jig is.  If Chris wants it to be a kind of its own, that
   is a new catalogue table and a decision.  Decision 0013.

2. **It answers only from the pin.**  jig/linux.pin names the one Linux commit
   (a5ebb762, the one all twelve lifts name).  `git show`, `git ls-tree` and
   `git archive` read it straight from the object store, so no checkout can
   differ from the pin, and a name, file or line range that is not in it is
   refused with a reason.  This is the check behind "the model can't invent
   code": whatever file and lines a model names, the reader either returns
   Linux's own bytes or says no.

3. **Names come from cscope, not from a model.**  find, callers and calls run
   cscope over a copy of the pinned tree.  The recorded answers (tests/expected/
   reader.find@1.out) were checked against a separate grep of the same file:
   serial8250_early_out is defined once (8250_early.c:59) and called ten times.

4. **Nothing is unbounded.**  At most READER_MAX lines (200) come back from any
   one question, so a model is never handed a whole file by accident, and a
   cut-short answer says how many lines it left out.

5. **Not checked yet.**  Everything above ran under Claude's workspace against a
   partial clone of Linux; the jig's run, with its own clone and cscope from
   configuration.nix, is the one that counts.  The jig needs `nixos-rebuild
   switch` for cscope to exist.

6. **The exam counts lines one way for both sides.**  `jig/runs count` takes
   the non-blank lines outside comments, the same rule for the model's lift and
   the hand lift, so the scorecard compares like with like.  By that count the
   hand lifts are 57 lines (serial8250.c), 103 (tsccal.c) and 55 (vga.c).  It
   does not understand a comment marker inside a string; no lifted file has one
   today, and the fixtures say what it does count.  The post's "Kernel code: K
   lines" is a different figure, kept by the as-built specs.

7. **A model with no price does not sit.**  `jig/runs record` computes a try's
   cost from jig/prices.toml and refuses a model that has no row, so a try is
   never recorded as free by leaving the price out.  The file is empty on
   purpose: a row goes in only from the provider's own price page, with its
   address and the day it was read, and a local model's row is 0 with the
   electricity not counted.  Nothing in the repo yet says what a Bedrock model
   costs.

8. **The cap is checked before the call.**  `jig/runs budget CEILING` refuses
   when this month's recorded cost plus the most the next call could cost would
   pass jig/budget.toml's cap (20 dollars, a number Chris can change).  The
   provider's budget alert is the second wall.  A call with no ceiling is not a
   call the runner may make.

9. **The scorecard is written down before it is drawn.**  The table in
   tests/expected/scorecard.table@1.out was worked out by hand (costs and
   tries for two made-up models) before jig/scorecard existed; the script has
   to match it.  The fixtures are labelled as fixtures, in tests/fixtures/exam,
   and the real scorecard reads only runs/.

10. **The judge.**  jig/judge takes an item and a folder holding the model's
    lift, stands it in for the hand lift in a throwaway copy of the repo, runs
    the item's tests there with jig/test, and says `pass N lines` or
    `fail N lines: <first red test>`.  The hand lift itself passes at 57 lines;
    a lift that never waits for the chip, one that sends an extra byte and one
    that is not C each fail.  It found a mistake in the exam on its first day:
    the serial item named the second serial part (69 lines) as the hand lift,
    but the three serial tests run the first (57 lines), so a broken copy of the
    second still passed.  The item now names the first, with its three tests.
    One mutation survives and is written down: a test that skips is not judged
    as a pass, but no test the exam lists skips on this host, so nothing sees it.

11. **Not built yet.**  The model runner (a call to Bedrock or the 3090) and the
    first run.  Those need the AWS key and Chris's choice of model.

12. **The model, the route and the price.**  On Bedrock the plain model id
    (anthropic.claude-sonnet-5-5) only takes an inference profile, and there are
    two: us.anthropic.claude-sonnet-5-5 and global.anthropic.claude-sonnet-5-5.
    The price on Bedrock's page, read 2026-10-17 for US West (Oregon), is in the
    table headed Global Cross-region Inference: 2.00 dollars per million input
    tokens and 10.00 per million output.  The exam uses the global profile
    because that is the price that was read; the US-only profile has no row.

13. **The account is refused the newest Claude.**  The first call to Sonnet 5.5
    came back 403 (not available for this account), the console playground says
    the same for Sonnet 5.5 and for Sonnet 5, and Sonnet 4.6 and Opus 4.6 answer
    there.  Checked and ruled out: no root access key, no user under AWS's
    compromised-key quarantine, the use-case form for Anthropic models is on file,
    and the last 90 days of CloudTrail show no change to model access and no
    Marketplace events (the last Converse calls are 2026-08-19).  The cause is not
    found; the account is refused the 5.x models.  The exam runs on Sonnet 4.6 and
    the 5.5 row waits for AWS (decision 0016).

14. **The runner, and what it is shown.**  jig/sit gives the model the question,
    the part's fixed header (the hand lift's .h, because the tests build against
    it and a lift cannot be judged without the names it must implement) and the
    reader as a tool; the lift itself, and everything else in the hand lift's
    folder, stays hidden.  The header is an interface, not an implementation, and
    the article should say so.  The runner is proved on saved replies with a
    stand-in reader and judge; the first real run is the first time it meets
    Linux and Bedrock together.
