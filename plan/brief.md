# AiOS project plan (brief)

One sentence per item.  Status in brackets: [done], [in progress], [coming up], [parked].
[parked] means decided not now, with the reason in the item.
The detailed plan is plan/full.md; this file is the one to read.

1. Constitution: the signed repo everything traces to. [done]
   1.1. Repo rules, ten tenets and purpose 0000 committed. [done]
   1.2. Petition schema with the catalogue tables and referee rules. [done]
   1.3. Petition 0000, hello world, written against the schema. [done]
   1.4. Findings 0000, the thirteen schema gaps, recorded. [done]
   1.5. Define the entry file formats for CAP, component, SPEC, TST and SNS. [done]
   1.6. Fix the review signing scheme so signatures live outside the file they sign. [done]
   1.7. Resolve the remaining gaps and publish the schema at version 2. [done]

2. The jig: the gen-zero host that turns the crank. [in progress]
   2.1. NixOS minimal on the existing box with one configuration of about twenty lines. [done]

   2.3. Every installed tool has a complete row in the tool table, including how it leaves. [done]
   2.4. KVM and QEMU VM definition with one serial port and no NIC, as a petition. [done]

3. Referee: no model, no judgment, fails loud. [in progress]
   3.1. Resolver that checks every catalogue number resolves to an entry at a version. [in progress]
   3.2. Relation checker for rules 1 to 10 that reports a rule number and a catalogue number, nothing else.  Rules 2 to 8 in `jig/aios rules`, written to tests/referee-results.txt (part 15, findings 0017); petitions 0004 to 0007 fail 4 and 6 until a decision says who exposes CAP.hv.kvmclock@1; the build gate still enforces 1, 9 and 12. [in progress]
   3.3. Expiry, status and quorum enforcement. [coming up]
   3.4. Artifact check for rule 11: the built image and VM against the petition.  Decided 2026-10-14: the builder writes a manifest of the parts it linked; the referee reads the image's symbol table and every symbol must trace to a part in the manifest, every part to the petition; the device half is today's TST.machine.*-only tests, which the referee runs itself (3.7).  Built 2026-10-23, part 21 (decision 0065): `referee artifact`, run by the builder on every linked kernel, holds each part in out/FLAVOR/kernel-parts.txt to the petitions and each exposed capability to what they ask, switched-off ones by their symbol in nm; what older kernels exposed unasked is listed in constitution/extras.toml and only shrinks.  Not built: every symbol traced to a part, and the device half. [in progress]
   3.5. Commit signature verification against constitution/keys (reviews became votes, decisions in the one log, 2026-10-15).  Decided 2026-10-14: an admission is a commit signed by a key in constitution/keys, verified with git's own SSH-signature check against that list (signed tags are how Linux has taken pull requests since 2011); a seat's vote is a decision in decisions/, signed by the commit that adds it, one per commit; no review files.  signify was considered; SSH is the one already in use. [coming up]
   3.6. Decision ledger: every agent decision declared with its options and who chose, checked against the diff so an undeclared one fails, with a human-only list; built before the committee.  Small version built for part 15: constitution/human-only.toml, decisions/, `jig/aios ledger`, the pre-commit hook; rule 12 (a program touches no hardware) checked after every build. [in progress]
   3.7. The referee runs the tester itself after every build, against that exact image, and says yes or no; the cache (5.4) takes only an image with that yes. [coming up]
   3.8. Deviations: a rule that matters goes in the constitution, with what breaking it costs written beside it (failure, debt fixed now, debt that can wait).  An agent may deviate, but must log a deviation decision (what it looked at, why it did not fit, what it built instead); the referee looks up the cost, never judges it.  How strict it is gets defined in one human-only file in constitution/, one line per rule, the way compilers and linters have long set each warning to off, warn or error: failure, fix now, or later, plus one switch that turns every later into a failure (for sealing a release); a deviation with no decision is a failure.  Every deviation lands on a debt list derived from the decisions.  Part 15. [coming up]
   3.9. The rule book, codified: constitution/rules.toml, one entry per rule with its plain sentence, its strictness, the check that enforces it, and the test that proves the check can go red.  The referee refuses a rule with no check (unless marked not enforced yet) and a check with no rule.  Checks are plain code plus a mutation test each, the way the referee works now (policy languages such as Open Policy Agent were considered).  Starts with an audit of rules 1 to 12: jig/aios names only 1, 9 and 12 in its refusals.  An agent post.  Part 15. [coming up]
   3.14. The referee in C: AGT.referee@1 in C, the language of everything permanent in AiOs.  The shell file was the spec by example: the C one must pass the same four probes, then the shell retires.  The ledger stays a jig script, it needs git; inside AiOs that job is admission.  The fifteen mutations are rewritten for C.  Rust was day one's "later, by petition, one part at a time" (CMP.editor@2 in the first handoff); if it ever comes, the referee is the candidate, by its own petition.  Done 2026-10-15, the same night: pool/AGT.referee@1/referee.c, 546 lines, the same four probes, fifteen mutations rewritten for C; jig/ledger stays shell.  Part 15. [done]
   3.13. The twelve settled 2026-10-15 evening, to build: rule 12's instruction list in constitution/ (done, and the referee moved into the pool as AGT.referee@1 the same night, decision 0008); the referee nightly on the jig for expiry; a signed verdict file per run; a change to a part's exposes or requires needs a decision until 3.10; a new rule applies to everything already admitted; strictness is the constitution's only; donecheck is ours; the rulebook points at design.md for the lifecycle jobs; use-it-or-lose-it as a sensor per capability, revoked at molt; the watchman triggers, never swaps.  posts/drafts/part-15-referee-questions.md has the words. [coming up]
   3.12. The referee runs where nobody types: today jig/test runs `jig/aios ledger --commit` on every commit since the last recorded run and refuses to test a commit that fails (built 2026-10-15); `jig/aios rules` joins the gate once the catalogue question (3.2) is decided; after the jig, the same check at admission inside AiOs.  The referee is permanent; only where it runs changes. [in progress]
   3.11. Rule 13 is built (`jig/aios lines`); 14 to 16 are written, not checked.  Decided 2026-10-15. [coming up]
   3.10. Rule 12, measured: for every part, not only programs, the referee reads the compiled code at build and logs its hardware footprint (every port, every privileged instruction, counted), then compares it to the as-built spec, which becomes the expected outcome a human decides; programs expect none.  A difference is logged, goes to review, and strictness (3.8) says whether it blocks.  Replaces hand-written as-built hardware lists with measured ones and shrinks the raw-bytes loophole in findings 0016.  Decided 2026-10-14; a lot of work, worth it. [coming up]

4. Tester: manufacture failures before the world does. [in progress]

   4.3. Mutation script that breaks the code on purpose and proves each test goes red. [done]

5. Builder: turn an approved petition into the system, deterministically. [in progress]
   5.1. Translator from a flavor to a build; a shell script now, a Nix expression when the jig exists. [in progress]
   5.2. Build that reproduces bit-identical on two hosts. [coming up]
   5.3. Live and shadow copies, swapped by the referee only on a passing shadow. [coming up]
   5.4. A launch names its applications; the first launch of a combination builds the nucleus for it, later launches reuse that build, keyed by exactly which applications at which versions. [coming up]
   5.8. The kernel is built from exactly the parts the petition names, never from everything the loader has ever gained: the petition is the partition.  Today the loader's catalogue entry depends on every part it has ever gained, which drags all of them into every petition and makes the referee refuse four petitions under rules 4 and 6 (findings 0017); under this rule the loader depends on almost nothing on its own, each petition adds the parts it needs, and the loader compiles with parts absent.  A runtime choice among parts (which clock) is allowed only when the petition asks for the chooser and lists the menu; the chooser is Linux's clock-source selection, lifted as a part, trimmed by the mechanic to the clocks present.  Decided by Chris 2026-10-15.  Built 2026-10-16: PART.loader@8 and PART.share@1, sort, the sieve and the editor moved onto it, the referee at 0 FAIL, TST.loader.partition@1 (decision 0011, findings 0018).  The chooser is not built (findings 0018 #4).  Part 16. [done]
   5.6. The builder works from a queue anyone can read: it builds what it can, sends the full list of what is missing to the quartermaster, and stops; an admission puts the flavor back in the queue and the run starts again from the referee. [coming up]
   5.7. Each part's compiled objects cached by exactly what went into them, so a rerun compiles only what changed; make and ccache are the history. [coming up]
   5.9. Test what changed, and the whole machine: after a change, run the tests whose part changed (each names it, isolates) plus the tests of the whole machine (the ladder, the screen, the partition check), because parts that pass alone can break each other (findings 0019 #3, the double-spaced screen); the whole suite runs on the jig every night.  Nothing changed means nothing rebuilt (5.4); one part changed means one part compiled (5.7); a petition removed means its parts are not switched on (5.8).  Decided by Chris 2026-10-16. [coming up]
   5.5. Adding an application without rebuilding the nucleus: today a new application means a new petition, new parts and a rebuild of the whole nucleus, worse than adding a driver to early Linux; Linux's answer then was loadable modules, the history to start from. [parked]

9. The ladder: one textbook program per petition, each fails on exactly one new thing. [in progress]
   9.1. Petition 0001, Towers of Hanoi: recursion, output only; no new system call, no new line in the loader, proving a second program changes nothing. [done]
   9.2. Petition 0002, Conway's Game of Life: the program asks for memory; the loader reads the machine's memory map and hands out pieces of it. [done]
   9.3. Petition 0003, a reverse-Polish calculator: the program reads; the serial part gains a receive side and the loader a read system call. [done]
   9.4. Petition 0004, a stopwatch: ticks once a second, counting up on one line until switched off; the program needs time passing, the microvm clock debt becomes a petitioned capability and the first real sensor. [done]
   9.5. Petition 0005, save the sorted output: an IDE disk driver and the original Minix filesystem lifted from Linux, the first expensive lift. [done]
   9.6. Petition 0006, two programs at once: the first thing that must be shared; the kernel appears, and every line of it is named. [done]
   9.7. Petition 0007, the console text editor, Notepad-plain: one file, no modes, every command on the bottom line (Ctrl+S, Ctrl+Z, Ctrl+Q); its one new thing is saving over a file (PART.fs.minix@2, Linux's truncate); no libc needed; C now, Rust later as PART.editor@2. [in progress]
   9.8. Every earlier program runs under every later loader; no system call ever moves. [in progress]
   9.9. The loop end to end: the quartermaster drafts the application's petition, the builder sends what is missing, the quartermaster drafts the parts, the committee votes, the flavor goes back in the builder's queue; the mechanic proposes and never installs. [coming up]
   9.10. The first Linux binary: a static Linux hello world runs unmodified on two system calls; every further Linux system call is petitioned by the first program that needs it. [coming up]
   9.11. BusyBox vi, unmodified: the capstone Linux binary, its system calls found by tracing it, each one a petitioned capability. [coming up]
   9.12. The clock on the screen: the time of day, not just time passing; the petition argues for a clock chip or asking the host. [coming up]
   9.15. Petition 0009, the screen: VGA text mode, 80 by 25, a character and a colour per cell at a fixed address; Life in colour, the first thing you can see; a new machine with a display and a new capability; QEMU's screendump as the tester's new sense, pixels not bytes; built on 5.8, the kernel from the petition, because only this flavor wants the VGA part.  Findings: a program writing the screen's memory is not a forbidden instruction, the first cheat rule 12 cannot see (9.13).  Chris, 2026-10-16.  Part 16. Built 2026-10-16: PART.screen.vga@1, MACHINE.serial-vga@1 (SeaBIOS runs the card's BIOS), PART.life@2, the screen tests, rule 12 failing closed (decision 0012, findings 0019).  [done]
   9.14. HashLife, Life that remembers: the first program that asks for more memory while running and gives it back; today a program gets its memory once, at load, and nothing can ask for more mid-run.  Suggested by a reader on part 5.  Not soon. [coming up]
   9.13. Programs lose the kernel's privilege: they run in ring 3 and the system call table becomes a gate they cannot step around.  Part 18. [in progress]
   9.16. cat, the first application from outside: Berkeley's cat (4.4BSD-Lite, 1994; V7's licence asks for advertising credit, which GPL-2.0-only does not allow), its petition drafted by a model, built by AiOs.  Part 19: the model drafts the petition, the referee checks it, the builder stops with a list of what is missing.  Part 20: musl lifted (only what cat links), a loader for Linux program files and thirteen of Linux's system calls, and cat prints a file on the jig; Berkeley's missing-file bug found red and fixed in its own change; a petition is now a human decision the builder checks.  TECH-DEBT 1 is not retired (findings 0023 item 12).  Findings 0022 and 0023. [done]
